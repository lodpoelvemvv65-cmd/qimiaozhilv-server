# GM 中文物品选择器

在角色详情点击“发放物品”，直接搜索中文名称或数字 ID，按物品分类与适用职业筛选，
点击结果中的“添加”，在已选列表填写数量。每次最多 100 种，每种 1～1,000,000,000 个。
数量不是整数、空列表、物品不存在或背包不足时拒绝发放。

“发送邮件”共用同一选择器，可添加多种附件、逐项填写数量或删除；不选附件可发送纯文字邮件。
附件随原生邮件协议发送，领取时才到账。GM API 在新邮件进入 Redis 控制队列前检查
ID、数量、附件上限与当前已发布物品；已完成命令的幂等重试保持原有结果。
修复旧 CSS 隐藏邮件内容框的问题，并补充弹窗键盘焦点、Esc 关闭与提交中禁止重复操作。

2026-09-14：「全服操作」页的**全服邮件**页签复用同一个选择器（权限 `server.mail_all`）。
它与单人发信共用同一套附件校验 —— 同一封信在哪个入口都该得到同样的答复。区别是收件人
为全部角色（含离线），附件校验因此更要紧：游戏服侧是一条写全表的 SQL，等它失败再回滚，
运营只会看到一句泛泛的「邮件保存失败」。该页签的确认框额外要求勾选「我确认向全部 N 个
角色发放」，读不到角色总数时禁止提交。

注意实测脚本会往本机库里**每一个**角色投递测试邮件：`verify_gm_broadcast.py` 每投递一封
就把 `mail_id` 打到 stdout，Go 侧按 id 精确删回。不能按 id 阈值一刀切清理 —— 库里正常的
单收件人邮件（战斗奖励、在线奖励）同样是 nanotime 生成的 id。

物品清单来自 MySQL `game_config_nodes` 中已发布的 `EquipBase`、`GoodsBase`、
`MaterialBase`。API 不读取 JSON、客户端资源或未发布的 YAML；每次读取获取当前配置，
前端缓存最多 30 秒。职业标签直接采用装备的 `JobId` 职业族：

| 职业类型 | 中文名称 |
|---|---|
| 0 / 未配置 | 通用 |
| 1 | 军官 |
| 2 | 运动员 |
| 3 | 护士 |
| 4 | 超能力 |

角色的 `players.job_id` 使用男女角色 1～8 编码，与装备的 1～4 职业族不同。
选择某个职业时同时保留通用物品；“仅通用物品”只显示无职业限制的条目。
同名装备可能有不同 ID、等级和职业，选择及去重始终以 ID 为准。

装备部位直接使用 `EquipBase.Type`，省略时为武器槽 0；不使用 `DetialType` 或强化属性。
页面与 CSV 显示武器、背景、形象、护腕、称号（勋章槽 4）、戒指、帽子、项链、
衣服、裤子、手套、鞋子。可组合“装备部位 + 职业”筛选，也可直接搜索“称号”等部位名。

- `GET /api/v1/items`：带中文名称、分类、等级、品质、职业和说明的物品目录。
- `GET /api/v1/items/export`：下载 UTF-8 BOM 中文 CSV，Windows Excel 可直接打开。
- 上述接口要求有效 GM 登录及角色查询、发物品、发邮件权限中的至少一项；没有配置编辑权限的客服也可查询。
- 离线清单可运行 `go run ./cmd/export-items` 更新，默认输出 `../文档/29-GM物品ID中文清单.csv`。
