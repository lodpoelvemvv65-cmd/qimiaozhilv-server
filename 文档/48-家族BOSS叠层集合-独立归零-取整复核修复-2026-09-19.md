## 1. 复核结论

另一份分析指出三处错误。对归档 JSONL 独立复算后，三项主结论全部成立：

1. 开场倍率作用 13 项，但战斗内周期叠层只作用 `1009~1012` 四项。
2. 四项共享 4.71 秒 tick 时刻，但层数按属性独立；modifier 只清实际触及属性。
3. 整数开场属性使用 Round，不是截断。

帧型计数有一处需要精确表述：严格按有序字段元组统计，`(1001,1011)` 是 26 帧；若忽略顺序并合并同类，则为 28 帧。该差异不影响上述三项结论。

## 3. 层数按属性独立

抓包同刻对照：

| 时刻 | 物攻 1009 / 开场基线 | 精防 1012 / 开场基线 |
|---:|---:|---:|
| 72.49 | 1.00 | 1.00 |
| 105.73 | 3.31 | 3.31 |
| 106.81 | 0.70，物攻被清零并带 `-30%` | 3.64，继续增加 |
| 120.81 | 1.00，减益到期再次清零 | 4.30，继续增加 |
| 298.70 | 1.69，物攻 n=2 | 16.84，精防 n=48 |

统一公式应写成按属性下标的形式：

```text
B_a = Round(MonsterBase_a × 开场倍率)
V_a = B_a × (1 + CharacterAdd × n_a + 外部百分比修正_a)
```

四项的 tick 时刻相同，但 `n_a` 不同。物攻/物防 modifier 的施加、新增层、移除或到期只清对应属性；同一活跃效果刷新不清零。精神防御没有被这些 modifier 触及，所以能持续累计到后期高值。

修复提交：

```text
ff18a2e fix(family): reset boss stacks per attribute
```

## 4. 开场整数属性使用 Round

五阶首帧：

```text
物防：2097080 × 1.53 = 3208532.40，Round = 3208532，抓包 = 3208532
精防：1689811 × 1.53 = 2585410.83，Round = 2585411，抓包 = 2585411
```

物防样本无法区分截断与四舍五入；精神防御样本可以。旧文档把首帧精防误读成 `2585410`，据此断言截断，是错误的。

修复提交：

```text
6cad36d fix(family): round opening boss attributes
```

## 5. 修复后实现边界

| 类别 | NumericType | 开场倍率 | 周期叠层 |
|---|---|---|---|
| HP | 1001~1002 | 否 | 否 |
| 双攻双防 | 1009~1012 | 是 | 是，逐属性层数 |
| 暴击率/值、辅助、抗暴 | 1013~1021 | 是 | 否 |
| 双免伤 | 1022~1023 | 否 | 否 |

全阶开场倍率仍按：

```text
1.20 + CharacterAdd = 1.25 / 1.28 / 1.35 / 1.43 / 1.53
```

其中只有五阶有线上抓包直接证据；1~4 阶仍是指定公式推导。
