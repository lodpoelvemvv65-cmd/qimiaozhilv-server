## 1. ★ 为什么能破防

### 1.1 BOSS 的防御会被削

从抓包里把 BOSS 的物防按时间排出来（`20170` 每次变化都重推）：

```
基础值   3,208,532   ← MonsterBase 2,097,080 × 1.53（见 doc 41）
战斗中   4,267,350   ← +1 层 CharacterAdd
         2,245,970   ← 被削 -30%
         1,347,580   ← 被削到最低（-58%）
         3,304,790   ← 又回到接近基础
         1,347,580   ← 再被削
         ...
```

**观测到的物防范围：1,347,580 ~ 6,385,000**（最小 / 最大）。

### 1.2 攻防差决定一切

| 玩家 | 职业 | 物攻峰值 | 魔攻峰值 | 面对 BOSS 物防 1.348e6 时 |
|------|------|----------|----------|--------------------------|
| 22233 | 运动员 | **4,071,000** | 51,680 | ✅ 能打穿 |
| 22234 | 军官 | 1,247,000 | 45,030 | ❌ 打不动（< 1.348e6） |
| 18937 | 超能力 | 34,000 | 2,830,000 | 物理打不动，法术看精防 |
| 22235 | 护士 | 75,630 | 2,299,000 | 同上 |
| 22240 | 超能力 | 80,490 | **3,362,000** | 同上 |

**验证**：运动员 22233 用 `210601 猛虎式射门`（配置 `Self = 270% 物攻`，Lv3）：

```
(4,071,000 − 1,347,580) × 270% = 7,353,234
抓包中该技能观测到的最大伤害      = 7,451,913     ← 差 1.3%
```

这里比较的是“观测到的攻击峰值、最低防御、最大伤害”，三者未证明发生在同一个结算时刻；
1.3% 的差值也不能直接归为取整，暴击更不可能只解释 1.3%。

**⇒ 能确认的是抓包与 `攻防差 × 技能系数、最低 1` 的形状相容；精确取值时点、暴击与其它修正仍未闭环，不能写成公式完全验证。**

### 1.3 反证：打不动的那些

抓包里 `伤害 = 1` 反复出现，来源正是**物攻低于 BOSS 物防**的玩家：

| 技能 | 施法者 | 配置 | 关联到的伤害值 |
|------|--------|------|---------------|
| 110304 冰霜弹 | 军官 22234（物攻 1.247e6） | 150% 物攻 | **1 ×2** |
| 410202 禁忌魔法 | 超能力 22240（魔攻 3.362e6） | 90% 魔攻 | 6,358,965（有伤害） |
| 400001 超能力普攻 | 22240 | `Self.calculateType=1`（魔攻）但 **`param.values` 为空** | 4,967,942（有伤害） |

**⇒ 同一个 BOSS 上，既有 1 点伤害也有百万伤害 —— 完全由「当时的攻防差」决定。**

> **2026-09-19 现状更正**：`400001 普通攻击` 的客户端参数空表问题已经由
> `battle_actions.go` 的 `onlineDamageLevelOverrides` 覆盖（Lv1 = 193%），
> `TestRealDamageAndCastCountModifiers` 与 `battle_test.go` 的超能力普攻用例均覆盖该行为。
> 因此它不再是待修项；是否还需补齐其它等级，要按实际可用等级另行核对。

## 2. 玩家（人物）的属性怎么算

### 2.1 服务端现状

```go
// growth.go:402
func (ss *session) playerPhyDef() int32 {
	return scaleStat(
		statSum(roundedDirectNumericBonus(ss, 1011), roundedCharacterGrowthValue(ss, 9)),
		starSoulSuitPercent(ss, 1011),
	)
}
```

即：**物防 =（装备/星魂/转生/宠物的 1011 之和 + `CharacterGrowth` 行 9x 换算）× (1 + 星魂套装%)**

`characterGrowthValue(9)` 用 `CharacterGrowth` 行 `9×10 + 职业族`：

| 行 | 职业族 | 系数 |
|----|--------|------|
| 91 | 军官 | `Phy × 9 + Sta × 46` |
| 92 | 运动员 | `Phy × 3 + Sta × 25` |
| 93 | 护士 | `Phy × 5 + Sta × 35` |
| 94 | 超能力 | `Phy × 3 + Sta × 25` |

精神防御同理（行 101-104：`Phy × 8 + Sta × 42` 等）。

### 2.2 抓包能看到什么

- **玩家的面板在战斗中会变**（`增加防御力` buff 会让 22234 的物防从 1.812e6 涨到 3.172e6），
  所以「基础值」要取**战斗开场第一次 `20170`**。
- 开场基础值：物防 774,400 / 498,200 / 1,812,000 / 1,022,000 / 714,700
- 物防 ÷ 精防 的比值：**1.17 / 1.05 / 1.27 / 1.00 / 1.04**
  —— 公式预期的比值约 **1.10**（`(9P+46S)/(8P+42S)` 在 P≈S 时 ≈1.10），**同量级**。
- **但要严格验证需要玩家的装备明细**（抓包推的是「装备+成长」的合成结果，拆不开），
  所以**本次无法对玩家防御公式下定论**。

### 2.3 ★★ 新发现：`RoleGrowth` 的属性成长系数完全没被使用

`datatable_json/RoleGrowth.json` 只有 **4 行**（每职业族一行），每行是一整套**按等级成长的系数**：

```json
{ "_id": 1,
  "ExpArr": [{ "Exp_BaseNumber": 0.01, "Exp_Power": 3 }],
  "Hp1": 85,  "Hp2": 6,   "Hp3": 260,
  "Vig1": 26, "Vig2": 5,  "Vig3": 40,
  "Str1": 2.85, "Str2": 0, "Str3": 0,
  "Quk1": 2.55, ...
  "Dvo1": 5e-06, "Dvo2": 5e-06, "Dvo3": 0,
  "PhyAtk1": 5, "PhyAtk2": 1.5, "PhyAtk3": 0,
  "SpiAtk1": 2, "SpiAtk2": 1.5, "SpiAtk3": 0,
  "PhyDef1": 0.5, "PhyDef2": 0.5, "PhyDef3": 0,
  "SpiDef1": 0.5, "SpiDef2": 0.5, "SpiDef3": 0 }
```

**服务端使用情况：**

```bash
$ grep -rn '"Hp1"\|"Hp2"\|"Hp3"\|"Vig1"\|"Str1"\|"PhyDef1"\|"SpiDef1"\|"PhyAtk1"' --include=*.go server-mysql/
（无输出）
```

**⇒ `Hp1..3 / Vig1..3 / Str1..3 / Quk / Spi / Wim / Dvo / PhyAtk / SpiAtk / PhyDef / SpiDef`
的全部系数都未被读取。** 服务端只用到了 `roleGrowth` 这一行的 **`ExpArr`**（而且升级经验实际是硬编码
`100 * floor(Lv³/100)`，只是与 `ExpArr{0.01, 3}` 等价，见 `battle.go:347` 的注释）。

**这是一整套「线上属性成长公式」，现在被完全忽略。**

**已知的困难**：直接用 Lv1 去套 `Str1=2.85` 与原版面板 Lv1 `Str=1` 对不上，
说明这三个系数的组合形式（`c1×Lv + c2×Lv² + c3×Lv³`？还是别的）**还没解出来**，
或者它的等级基准不是「当前等级」。

**⇒ 登记为待逆向项**（doc 11 称它是「线上属性公式」，但至今没有定论）。
不要凭猜测去改 —— 玩家属性公式一动会牵连全服数值。

## 3. 对本服务端的结论

| 项 | 判定 |
|----|------|
| **伤害公式 `(攻 − 防) × 百分比`，最小 1** | ⚠ 与线上样本的整体形状相容；现有比较混用了峰值/谷值，精确系数尚未验证 |
| **玩家防御公式（装备 + `CharacterGrowth` 行 9x）** | ⚠️ 抓包**无法定论**（缺装备明细）；但**面板比值与公式预期同量级** |
| **`RoleGrowth` 属性系数未使用** | ❓ **待逆向** —— 可能是玩家属性公式缺失的一块 |
| **`400001 超能力普攻` 的 `param.values` 为空** | ✅ 当前已用 Lv1 193% 线上覆盖值修复并有单测，不再列为待修 |
| 家族BOSS 防御低 34.6% | ❌ 见 `文档/41`（缺 `CharacterAdd` 倍率） |

import json,io,struct,re,collections
def dec(h):
    b=bytes.fromhex(h); out={}; i=0
    while i<len(b):
        k=b[i]; i+=1; f=k>>3; w=k&7
        if w==0:
            v=0;s=0
            while i<len(b):
                x=b[i]; i+=1; v|=(x&0x7f)<<s; s+=7

            out[f]=v
        elif w==5 and i+4<=len(b): out[f]=struct.unpack_from('<f',b,i)[0]; i+=4
        else: break
    return out
rows=[json.loads(l) for l in io.open('_work/pcap_frames/online-control-resist-20260918.jsonl',encoding='utf-8') if l.strip()]

for u in sorted(mx):
