# 18 - 星魂系统（StarSoul）完整协议与客户端逆向分析

> 分析对象：Hotfix.dll / HotfixView.dll（`<原版客户端>\梦幻奇遇记_Data\StreamingAssets\yoo\_extracted`）
> 协议清单：protocol_dump.txt opcode 20395~20425；数据表：`datatable_json\StarSoul*.json`
> 结论速览：
> - 星魂 = 可穿戴到 12 个装备槽位（`ET.EquipType`）的养成道具，含品质(1~6)、等级(0~20)、经验、主属性+副属性、套装效果（4件/8件）。
> - 拉包入口：进图 1 秒后 `unit.StarSoulBag.InitData()` → **20396 C2M_GetStarSoulBag → 20400 M2C_GetStarSoulBag**；当前 `server-mysql` 完整返回 itemList/usedIdMap/suitKVs。
> - 增量同步走 3 条服务端推送：**20401 全量 / 20402 单件 / 20403 穿戴映射+套装**；其中仅 **20402** 的 Handler 更新后同步 Publish `RefreshStarSoulBagUI` 事件刷新界面（20401/20403 只更新本地数据，不发布 UI 事件）。
> - 查看其他角色时，服务端在 `M2C_GetCharacter(20252)` 后追加目标角色的 `20401` 全量星魂，并把 `UnitId/ActorId` 设为目标角色 ID；不得混入查看者自己的星魂背包。

## 1. 功能概述与入口

**功能**：星魂背包（StarSoulBag，容量上限 1000，见 `StarSoulBagSystem.CanAdd` 内 `ItemCount < 1000`；组件另含字段 `MaxCount`（上限）、`lastSortTime` / `sortTimeIntervel`（排序冷却时间戳/间隔））、穿戴到 12 个装备部位（`ET.EquipType`：武器/背景/形象/护腕/勋章/戒指/帽子/项链/上衣/裤子/手套/鞋子，枚举值 0~11）、升级（吃材料+金币）、锁定、分解（单件/全部）、通过副本（StarSoulCopyConfig）获取新星魂。

**界面与入口链**：

### 3.1 Handler（Hotfix.dll，TypeDef 266/267/268）

**M2C_SyncStarSoulBagInfoHandler（20401）** — `<Run>d__0.MoveNext`：

**M2C_SyncStarSoulBagHandler（20402）** — 单件更新：
```

if (message.item.Id != 0) {
    var item = new StarSoulItem { Id=item.Id, isUsed=item.isUsed, typeId=item.typeId,
        mainAttribute=item.main, level=(byte)item.level, exp=item.exp,

    bag.Update(item)                       // 返回 bool；有则 set_Item，无则 Add
    Debug.Log(...)
} else {
    bag.ItemDic.Remove(message.Id)          // item.Id==0 → 删除
}
Game.EventSystem.Publish<RefreshStarSoulBagUI>(new RefreshStarSoulBagUI { zoneScene = ... })  // 同步 Publish（callvirt Publish）→ 刷新界面
await ETTask.CompletedTask                 // 纯 yield（Publish 之后单独 await）
```
注意：net 消息里 `Id`(tag1) 与 `item.Id`(tag1 in item) 是两个字段；删除语义用 `item.Id==0` 触发，删除键取 `message.Id`。

## 4. 相关数据表结构与字段语义（datatable_json\StarSoul*.json）

JSON 均为 `[key,{...}]` 二元组（读取前需 `re.sub(r',\s*([\]\}])', r'\1', s)` 去尾逗号；原文件 UTF-8 被 GBK 误读显示为乱码，中文按 UTF-8 还原）。

### 4.1 StarSoulTypeConfig.json（10 行）—— 星魂类型
| 字段 | 类型 | 语义 |
|---|---|---|
| _id | int | 类型 Id（1001~1010） |
| Name | string | 名称 |
| Icon | string | 图标资源名（如 "120682"） |
| CopyType | int | 所属副本/掉落组（1~5，对应 StarSoulCopyConfig.Type） |
| Suit4Key / Suit4Value / Suit4 | int / float / string | 4 件套效果：属性键（Cal.AttributeType 32~39、27、29）+ 加成值 + 描述文本 |
| Suit8Key / Suit8Value / Suit8 | int / float / string | 8 件套效果（仅 1009 螣蛇有） |

示例：
```
1001 {"_id":1001,"Name":"太阳烛照","Icon":"120682","CopyType":1,"Suit4Key":32,"Suit4Value":0.4,"Suit4":"攻击+40%"}
1009 {"_id":1009,"Name":"螣蛇","Icon":"120681","CopyType":5,"Suit4Key":27,"Suit4Value":0.05,"Suit4":"吸血率+5%","Suit8Key":28,"Suit8Value":0.1,"Suit8":"吸血量+10%"}
```
Suit4Key 与 `Cal.AttributeType` 枚举对齐：32=攻击加成、33=防御加成、34=生命加成、35=精力加成、36=暴击系数、37=暴击效果、38=抗暴击系数、39=抗暴击效果、27=吸血率、28=吸血量、29=生命回复。

### 4.2 StarSoulLevelConfig.json（126 行）—— 等级经验（Quality 1~6 × Level 0~20）
| 字段 | 类型 | 语义 |
|---|---|---|
| _id | int | 10001 + (Quality−1)*21 + Level（全部 126 行验证成立：Q1L20=10021、Q2L0=10022、Q6L20=10126） |
| Quality / Level | byte | 品质 / 等级 |
| NeedExp | int | 当前等级升到下一级所需经验（客户端进度条上限） |
| Exp | int | 该 (品质,等级) 星魂**作为升级材料时提供的经验**（Q1 Lv0=50，每品质翻倍：100/200/400/800/1600） |
| NeedCoin | int | 每次升级消耗金币（材料按各自 (quality,level) 的 NeedCoin 累加） |

示例：
```
10001 {"_id":10001,"Quality":1,"Level":0,"NeedExp":0,"Exp":50,"NeedCoin":12}
10021 {"_id":10021,"Quality":1,"Level":20,"NeedExp":10000,"Exp":57944,"NeedCoin":32}
10126 {"_id":10126,"Quality":6,"Level":20,"NeedExp":75937,"Exp":315620,"NeedCoin":420}
```

### 4.3 StarSoulAttributeConfig.json（150 行）—— 属性基础值
| 字段 | 类型 | 语义 |
|---|---|---|
| _id | int | 1001~1150，**StarSoulNetItem.main / vice 直接存此 Id** |
| Type | byte | 属性池组（1=低阶 120 行含 Quality；2=高阶 30 行无 Quality 区分） |
| Quality | byte | 品质（1~6，仅 Type=1 有） |
| Key | byte | 属性键 = `Cal.AttributeType`（1=最大生命、2=最大精力、7=物理攻击、8=精神攻击、9/10=物理/精神防御、11~18=暴击系、25=命中、26=抵抗、30/31=物理/精神增伤 等） |
| Value | float | 基础属性值 |
| ViceWeight | byte | 该属性作为副属性出现时的随机权重 |

示例：
```

1101 {"_id":1101,"Type":1,"Quality":6,"Key":1,"Value":89186,"ViceWeight":5}
1121 {"_id":1121,"Type":2,"Key":1,"Value":96000,"ViceWeight":20}   // Type=2 无 Quality 字段
```
客户端属性预览公式（`TabHelper.GenerateStarSoulString` + `ItemHelper`）：
- 主属性实际值 = `Value × Math.Pow(1.1f, level)`（`GetRealMainValue`）
- 副属性实际值 = `Value × 档位系数`，档位由 `viceAdd[i]` 决定：`<1 → ×1.0`，`<2 → ×0.8`，`<3 → ×0.48`（`GetRealViceValue`）
- 套装：`bag.Suits.Find(s => s.type.HasFlag(对应星魂的 Suit4/Suit8))` → 显示 Suit4/Suit8 文本

        suitKVs: toKVs(p.Bag.Suits) }   // key=typeId, value=suitType
    return resp  // Error=0
}

// 20406 PutonStarSoulItem：穿戴
func Puton(p *Player, itemId int64) *M2C_PutonStarSoulItem {
    it := p.Bag.Items[itemId]; if it == nil || it.IsLocked || it.IsUsed { return err("...") }
    if old := p.Bag.Items[p.Bag.UsedSlot[it.PosType]]; old != nil { old.IsUsed = false; old.PosType = -1 }
    p.Bag.UsedSlot[it.PosType] = itemId
    it.IsUsed = true
    RecalcStarSoulAttrs(p)                       // 重算并入 NumericComponent
    p.Session.Send(M2C_SyncStarSoulBag{ Id: itemId, item: toNetItem(it) })            // 20402 单件
    p.Session.Send(M2C_SyncStarSoulBagItemUsed{ key: it.PosType, value: itemId, suitKVs: toKVs(p.Bag.Suits) }) // 20403
    return ok
}

// 20404 UpgradeStarSoulItem：升级（itemId=目标，idList=材料）
func Upgrade(p *Player, itemId int64, idList []int64) *M2C_UpgradeStarSoulItem {
    target := p.Bag.Items[itemId]; if target == nil || target.IsUsed || target.IsLocked { return err() }
    var coin, exp int64
    for _, m := range idList {
        mat := p.Bag.Items[m]; if mat == nil || mat.IsUsed || mat.IsLocked { return err("材料不可用") }
        lv := StarSoulLevelConfig[quality: mat.Quality, level: mat.Level]
        coin += lv.NeedCoin; exp += lv.Exp
        delete(p.Bag.Items, m)
    }
    // 扣金币（NumericComponent Coin -= coin，不足返回 err）
    target.Exp += int32(exp)
    for {  // 等级提升
        need := StarSoulLevelConfig[quality: target.Quality, level: target.Level].NeedExp
        if target.Exp < need || target.Level >= 20 { break }
        target.Exp -= need; target.Level++
    }
    RecalcStarSoulAttrs(p)
    p.Session.Send(M2C_SyncStarSoulBag{ Id: target.Id, item: toNetItem(target) })   // 20402
    for _, m := range idList { p.Session.Send(M2C_SyncStarSoulBag{ Id: m, item: &StarSoulNetItem{Id: 0} }) } // 删除材料
    return ok
}

// 20424 GetStarSoulItem：先校验并扣除 30 个 20283 星魂碎片；configId/100=typeId,

// 20409 StartActive：itemId=ActivePerDayConfig.Id，判活跃进度 → 发奖（可能含星魂）→ 20410

//   quality = 按副本/来源随机
//   main    = 从 StarSoulAttributeConfig[Type,Quality] 按 Key 主属性池选一个（如 Key∈{1,2,7,8,9,10,19} 的常用主属性）
//   vice    = 按 StarSoulEquipAttributeTypeConfig[posType].AttributeTypeArr 加权随机若干条，
//             每条对应 StarSoulAttributeConfig[Type,Quality,Key] 且按 ViceWeight 加权；viceAdd[i] = 随机档位(0/1/2)
//             品质决定初始条数（1/1/2/2/3/3），每提升到一个 4 的倍数再解锁一条，最高 4 条随机副属性；

### 5.3 属性并入 NumericComponent（关键点）
- 星魂主属性/副属性为固定数值，按 `Cal.AttributeType`（1~39）键折算进 `NumericComponent` 的对应 `ET.NumericType`（如 1→MaxHp、2→MaxMp、7→PhyAtk、8→SpiAtk、9→PhyDef、10→SpiDef、11/12→Pcrir/Mcrir、13/14→Pcri/Mcri、15/16→Rpcrir/Rmcrir、17/18→Rpcri/Rmcri、25→Hit、26→Res、27→SuckR、28→SuckV、29→HpRecover、30/31→PhyDA/MicDA 等）。
- 套装加成：按 `Suits[typeId]` 计算同类型已穿件数（`StarSoulTypeConfig` 一行 = 一个类型套装；达到 4 件生效 Suit4，达到 8 件生效 Suit8，1009 两段都有），加成值为百分比（Suit4Value/Suit8Value），乘到对应基础属性上（Key 32~39 分别对应 攻击/防御/生命/精力/暴击系数/暴击效果/抗暴击系数/抗暴击效果）。
- 穿戴/升级/分解后统一 `RecalcStarSoulAttrs`，结果写入 NumericComponent 并随属性同步消息推给客户端（客户端无本地计算逻辑，只做展示）。
- `CharacterUI.ShowEffect` 按当前查看窗口的角色 ID 解析已穿戴星魂。服务端查询角色时必须紧随角色快照推送
  该目标的完整星魂背包；本地装备悬浮补丁同样固定读取 `CharacterUI.id`，不再依赖可能已经变化的全局 `SelectUnitId`。

## 6. 验证要点（协议脚本断言）

1. **拉包**：登录进图 1 秒后应收到 C2M_GetStarSoulBag（opcode 20396，RpcId 递增）；服务器回 20400 时 **必须带字段级字段**：`tag=1 itemList`（可空列表也要编码 `field 1, len 0`）、`tag=2 usedIdMap`（12 个 int64，全 0 表示空）、`tag=5 suitKVs`。
   ⚠ 2026-09-14 更正：原文接着写「当前只回 `{Error,Message}` 会导致 `FillData` 拿到 null 列表」——
   该风险**已不存在**，`server-mysql/starsoul.go:635` 始终填充这三个字段级字段。
2. **20400 断言**：itemList 内每个 StarSoulNetItem 检查 tag 1/2/3/4/5/6/7/8/11 及**字段级 tag 9 (vice, repeated int32) / tag 10 (viceAdd, repeated float)** 是否齐全；`usedIdMap[i]` 对应槽位 i 的实例 Id，与 itemList 中 `isUsed=true` 的项一致。
3. **穿戴**：发 20406 {itemId} → 收 20407 Error=0 → 应随后收到 20401（或 20402+20403）；20403 的 key=posType、value=itemId，suitKVs 反映套装件数。
4. **升级**：发 20404 {itemId, idList=[材料...]} → 20405 Error=0 → 收 20402：目标 level/exp 变化；材料以 `item.Id==0` 的 20402 删除；金币按 StarSoulLevelConfig.NeedCoin 累加扣减。
5. **锁定**：发 20408（isLock=true）无响应 → 应收到 20402 且 isLocked=true；重复操作幂等。
6. **分解**：发 20413 {ids} → 20414 的 `itenList`（tag 1，repeated RewardItem）非空且 Id/ItemType/Count 合法；随后 20402 删除对应实例。
7. **获取**：拥有至少 30 个 20283 碎片时发 20424 {configId} → 20425 Error=0 → 收 20402 新增实例；服务端扣除 30 个且 `configId = typeId*100+posType` 拆解校验，类型/部位固定、属性随机；不足 30 个时余额和背包均不变。
8. **属性生效**：穿戴后对比前后 NumericComponent 属性推送，主属性 ≈ `Value × 1.1^level`（可容忍取整），套装加成按件数生效。
9. **查看他人**：查看目标角色后应依次收到目标 Numeric/20252/20401；20401 的 `UnitId`、`ActorId`、
   `itemList` 和 `usedIdMap` 必须全部属于目标角色，不能返回查看者自身星魂。
