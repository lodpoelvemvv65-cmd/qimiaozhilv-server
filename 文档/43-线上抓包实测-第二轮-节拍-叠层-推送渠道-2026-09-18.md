## 1. ★ `500010` 中毒跳伤间隔 = 3.5 秒（持续治疗是 4.0 秒）

### 1.1 DoT 的实测

BOSS 的 `500010 烈风（中毒）`（`Time=26000`，26 秒）挂在玩家身上后，**同一目标**的负向伤害帧：

```
中毒 22240  施加 197.15s → 207.65  211.15  214.65  218.15  221.65        间隔 3.50 ×4
中毒 22233  施加 201.86s → 208.86  212.36  215.85  219.36  222.85  226.35 间隔 3.50 ×5
```

- 两个窗口、共 **10 个间隔全部是 3.500 秒**（不是 3.4 也不是 3.6）；
- **末跳都落在 +24.5s**，正好 `= 7 × 3.5`，与现有规则「跳数 = `floor(持续时间 / 间隔)`」自洽：`floor(26/3.5) = 7` ✅；
- 跳伤数值**同一次施加内基本恒定**（22233：375768→422708→394396→391934→376096→376629，抖动 ±6%），
  且**不随 BOSS 攻击力叠层变化**（该窗口内 BOSS 物攻从 3.78e6 涨到 7.42e6，跳伤没跟着翻倍）
  ⇒ DoT 数值在**施加瞬间定死**，之后只按节拍扣。

> 全包「相邻负向伤害帧间隔」直方图里，**3.5s 出现 19 次**，是除"同拍多目标"(0.0s) 与"0.5s 拍"以外最集中的一种。

### 1.2 同一份包里的对照组：持续治疗 = 4.00 秒

35 次 `bufficon_constrea`（`Time=14000`）全部呈同一形态：

```
+4.00 / +8.00 / +12.00 秒 各一跳，+16.00 秒那跳（已超出 14 秒）从未出现
```

⇒ `floor(14/4) = 3` ✅。**这是文档 35 §F10 里那条 4s 结论的独立复现**，说明 4s 对**持续治疗**是站得住的。

### 1.3 ⇒ 结论：至少本场中毒与 HOT 的节拍不是同一个常量

| 效果 | 实测间隔 | 我们服务端 |
|------|----------|-----------|
| 持续治疗（`bufficon_constrea`） | **4.000s** | 4000ms ✅ |
| 持续伤害（`bufficon_poisoning`） | **3.500s** | 4000ms ❌ |

我们这边是**一个全局常量** `Gameplay.combat.effect_tick_interval_ms = 4000`
（`config/operations/Gameplay.yaml:113`），`periodicTickInterval()` 忽略入参直接返回它，
`battle_periodic_tick_test.go` 还断言流血/中毒/点燃/持续治疗**四者都是 4000ms**。

> ⚠ **诚实标注（两点）**
> 1. 中毒的**前 1~2 跳在抓包里没有对应的 `20078` 帧**（8 个可观测窗口里 5 个如此；
>    例如 22240 的 +3.5s/+7.0s 缺失。可能是被后续施加刷新重置了计时器、也可能是被护盾吸收，
>    现有数据分辨不了），所以**首跳规则对 DoT 还不能定死**；能定死的是"间隔 3.500s + 末跳 +24.5s"。
> 2. 本结论只覆盖 **BOSS 的 `500010 中毒`** 一个 DoT。进一步复核效果树后更正：
>    `50001035` 是外层 modifier，真正承载 event 8 周期中毒的是其挂入的
>    `modifier 50001033`；后者 `thinkInterval` 为空，配置里没有 3.5 秒节拍，
>    因而仍只能靠抓包测。服务端按实际周期节点 `50001033` 配置覆盖。
>    **要坐实"DoT 一律 3.5s"，还需要一次只有单一 DoT、没有护盾、不被重复施加的抓包**（见 §9）。

## 2. ★ BOSS 战斗内叠层：4.71 秒时间网格 +1 层（**不是"每次施法"**）

文档 41 已经测出开场 13 项基线 `B = MonsterBase × 1.53`；本节进一步确认只有双攻双防按层数变化。
第二轮定案 + **第三轮（2026-09-19）独立复算更正**：

**① ⚠ 驱动力落在 `4.71 秒` 时间网格上，不是 BOSS 的施法。**
第二轮只挑了"对齐得很整齐"的样本（下左），第三轮把 **92 个物攻变化点逐个去找同刻（±0.06s）BOSS 施法**，
**有 30 个点找不到**（下右）：

```
（第二轮列出的对齐样本）              （第三轮补上：同刻没有 BOSS 施法的变化点）
BOSS 施法    77.48  82.19  91.60 ...   72.49 86.90  96.31  101.02 106.81* 120.81* 125.03*
物攻变化点   77.48  82.19  91.60 ...   138.67* 139.03* 143.38 157.50† 166.91 207.02* 209.27
                                       228.10 232.81 234.68 257.12* 284.78 289.00* 289.29
（* = 同刻有 20077 效果帧，但不是 BOSS 施法；  303.00 308.11 320.88* 334.88 357.32* 371.32
  † = 同刻只有玩家（非 BOSS）施法）       374.01 384.65* 398.65
```

而 **BOSS 的 62 次施法之间也有 11 个 `4.71s` 格点被跳空**（间隔直方图：
`4.70×1 / 4.71×50 / 9.41×6 / 9.42×1 / 14.12×3`），**但那些格点上层数照样 +1**。

**⇒ 正确表述：层数按 `4.71 秒` 时间网格 +1；BOSS 的施法通常落在同一格点上（所以看起来"逐次对应"），
但它不是原因。抓包支持独立周期机制，却不能直接证明线上内部对象就是一个定时器。照抄"每次施法 +1 层"会在"施法被跳过/被眩晕"的回合漏掉一层。**
（复算：`tools/_cap39_recheck_D.py` → `_work/cap39_recheck_D.txt`）

**② 节拍是 4.71 秒，不是 5 秒。** 相邻施法间隔稳定在 **4.706~4.710s**；偶发整拍跳过
（`9.41 = 2×4.71`、`14.12 = 3×4.71`），不是随机抖动。

相位补充：开场全量帧在 `72.49s`，第一个 +1 层帧在 `77.48s`，相差约 `4.99s`；后续真实间隔约
`4.708s`，向前外推的网格起点约在开场后 `0.28s`。当前服务端从 `startedAt+4.71s` 起算，约早 `0.28s`；
这不影响同样战斗时长内的跳数和数值，只在将来逐帧对齐时需要进一步校准。

**③ 公式精确到个位，且层数与 debuff 是「加法叠加」而不是相乘：**

```
令 B_a = Round(MonsterBase_a × 1.53)（本次 5 阶战斗属性 a 的开场基线）
面板_a = B_a × (1 + CharacterAdd × n_a − Σd_a)

3,672,000 × (1 + 0.33 − 0.30) = 3,782,160   ← 抓包实测 3,782,160（1 层 + 玩家给的 −30%）
3,672,000 × (1 + 0.33 × 14)   = 20,636,640  ← 抓包实测 20,636,640（满层，无 debuff）
```

⇒ 玩家的降攻/降防 **不乘在叠层后的总值上**，而是和对应属性的 `CharacterAdd×n_a` 加在同一个开场基线上。

> ⚠ **2026-09-19 更正：`Σd` 不只 −30%，至少四档。** 物防序列上还观测到
> **−25% / −28% / −58%**（对应比值 `0.75 / 0.72 / 0.42`），以及 `+3% / +5%` 的增量
> （`1.03 / 1.05` 与 `1.33 / 1.66` 之差）。全部取值都能分解成 `1 + 0.33n − Σd`：
>
> | 观测比值 | 分解 | 例 |
> |---|---|---|
> | `1.00 / 1.33 / 1.66 / 1.99` | `1 + 0.33n`（n=0..3） | 无减益时的叠层 |
> | `0.70 / 1.03 / 1.36 / 1.69` | `(1 + 0.33n) − 0.30` | **−30%，来源已定 = 运动员 `210603 开大脚`** |
> | `0.72 / 1.05 / 1.38` | `(1 + 0.33n) − 0.28` | −28%，来源未定 |
> | `0.75` | `1 − 0.25` | −25%，来源未定 |
> | `0.42` | `1 − 0.58` | −58%，`文档/42` §1.1 记的那一档，来源未定 |

**④ 层数上限与清零（★ 2026-09-19 把清零条件定死了）**

观测到的最高层是 **n = 14**（`3,672,000 × 5.62 = 20,636,640`）。
这**不是硬上限**，而是最长的一段无干扰区间：`139.03s → 204.56s` 共 65.53 秒，
`65.53 ÷ 4.71 = 13.9` 拍。

**清零条件 = BOSS 身上某属性的"层数以外百分比修正"被施加或到期时，只清该属性的 `n_a`。**

```
20077 {1: 22233, 4: BOSS, 9: 2233}（开大脚命中帧）出现的时刻 →
   106.81  125.03  138.67  207.02  257.12  289.00  320.88  357.32  384.65
物攻比值跌到 0.70（层数归零 + −30%）的时刻 → 与上面同刻（138.67 那次为刷新，见下）
物攻比值回到 1.00（减益 14.0s 到期、层数同样归零）的时刻 →
   120.81  139.03  234.68  284.78  303.00  334.88  371.32  398.65
```

- **来源已定**：运动员 `210603 开大脚`。`20075` 施法 → **+1.00s** 发 `20077 {EffectId 2232, Time=1000}`（释放）
  → **+2.00s** 发 `20077 {EffectId 2233}`（命中），给 BOSS **−30% 物攻 + −30% 物防**。
  8 次观测全部严格 +2.00s（`104.81→106.81`、`123.03→125.03`、`205.01→207.02`…）。
- **减益持续恰好 14.0s**：`106.81+14.0 = 120.81` ✅、`125.03+14.0 = 139.03` ✅、
  `289.00+14.0 = 303.00` ✅、`320.88+14.0 = 334.88` ✅、`357.32+14.0 = 371.32` ✅、`384.65+14.0 = 398.65` ✅。
- **"从无到有"才清零，"刷新"不清零，"到期"清零**：`138.67` 那次命中时减益仍在生效期内
  （`125.03 + 14.0 = 139.03`），比值是 `1.69 = 1.99 − 0.30`（n=3）而不是 `0.70` ⇒ 刷新没有清零。
- **各属性独立**：`106.81s` 物攻从 3.31B 变为 0.70B，但精神防御继续从 3.31B 增至 3.64B；
  `298.70s` 物攻只有 1.69B（重置后 n=2），精神防御已到 16.84B（n=48）。物攻减益不能清掉精神防御层数。

> **⇒ 可直接实现的规则：**
> 双攻双防共享 4.71 秒 tick，但各自 `n_a` 独立 +1；某属性的外部百分比修正被施加或到期时只清该属性，持续期内刷新不清零。
