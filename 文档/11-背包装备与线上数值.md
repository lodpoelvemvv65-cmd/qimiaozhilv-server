# 11-背包装备与线上数值



> 逆向还原《梦幻奇遇记》的背包 / 装备穿戴 / 角色数值体系：协议结构（Hotfix.dll 反汇编）、

> 线上属性公式（RoleGrowth.json）、装备属性并入（EquipBase.json → NumericType）、

> 服务器实现（`server/equip.go` / `server/growth.go` / `server/pb_extra.go`）。

>

> 结论先行：**客户端不计算角色属性**——属性全部由服务器算好，经

> `M2C_SyncUnitAttribute(20169)` / `M2C_SendCharacter(20257)` / `M2C_GetCharacter(20252)` 推送，

> 客户端仅显示。线上公式只能从 RoleGrowth 表字段结构推断（客户端零引用，见 §2 推断依据）。

### 1.3 客户端渲染逻辑（HotfixView.dll 反汇编）



- **BagUI.AwakeAsync**（rid 1047）：`new C2M_GetBag()` → await `M2C_GetBag` →

  若 `Message` 非空弹提示，否则发 `UpdateBagUI{list=BagMapList}`；每格绑定

  onClick（双击 → `C2M_PutOn{Index}` / 物品 → `C2M_UseGoods{Index}`）、onRightClick、拖拽等。

- **UpdateBagUIEvent.Run**（rid 140）：`ItemDic[Index] = ClientItemData`；

  渲染时 `EquipBase[ItemId].IconName` / `GoodsBase[ItemId].IconName` 取图标，Count 显示数量。

- **M2C_PutOn 处理**：`UpdateBagUI{BagMapList}` + `UpdateWornEquipUI{WornBagMapList}`。

- **UpdateWornEquipUIEvent.Run**（rid 147）：`WornEquipDic[BagMap.Index] = 装备`；

  若 FUI_CharacterUI 打开则刷新角色面板（`m_atkEquipList` 攻击装备 / `m_commonEquipList` 通用装备列表）。

- **CharacterUI.AwakeAsync**（rid 1056）：打开面板 → `new C2M_GetCharacter{Id=SelectUnitId}` →

  await `M2C_GetCharacter` → `ClientUnitCharacterComponent.Update(UnitCharacter)` → `ShowNumText`。

- **M2C_SendCharacterHandler**（rid 260）：`ClientUnitCharacterComponent.Update` + 若 `Id==MyId` 发 `UpdateCharacterUI`。



### 1.4 穿戴槽位语义



`WornBagMapList.BagMap.Index` = 槽位号。服务器取值规则：

**槽位 = EquipBase.Type**（8=背心 9=裤 10=手套 11=鞋，Type 1-7 其他部位）；

**武器类装备 Type 为空 → 枚举默认值0，即武器槽**。`SpecialKey` 是装备强化主属性的 `AttributeType`，不能用于穿戴槽位。

Type 分布：1(20)/2(92)/3(25)/4(24)/5(14)/6(26)/7(19)/8(149)/9(149)/10(125)/11(137)/None(216)。



## 2. 线上属性公式（RoleGrowth.json）



### 2.1 反汇编结论：客户端不计算属性



- `Cal.DataTable.RoleGrowth`（Hotfix rid 120）在客户端**零引用**（MemberRef/IL 扫描 0 命中），

  `CharacterHelper` 只有 GetJobTypeById/SexToSTring/GetLevelString 工具方法。

- 属性显示链路 = 服务器推送：`M2C_SyncUnitAttribute(20169)`（单条）→

  `NumericComponent.SetAsInt` → 面板 `NumericComponent.GetAsInt` 直接显示。

- 因此线上公式只能由数据表 + 线上抓包反推。**2026-09-13 起服务器已改用原版面板实测值校准**，

  运行时不再使用 RoleGrowth 二次项（见 §2.3）。




> ⚠ 上表只用于离线逆向对照。`00–33` 之后服务端已删除全部 `baseMaxHp/baseStr/…` 与

> `maxHpAt/attrAt` 等 RoleGrowth 助手（commit `77f9fc8`、`33ed760`），面板属性改由

> CharacterGrowth + 抓包实测基值计算，**不要再用 `X1 + X2*Lv + X3*Lv²/100` 推导当前面板**。



### 2.3 当前属性模型（`growth.go`，2026-09-13 线上抓包校准）



```

六维基值 naturalPrimaryStat = ⌈阶段等级 / 10⌉      （1 级就是 1 点）

阶段等级 stageLevel = 总等级 - transLevelStart[转生阶]

transLevelStart = {0, 6000, 13000, 21500, 31500}，转生上限 3 阶



playerStr  = 六维基值 + strAdd + 直接数值加成(1005)

playerMaxHp = (直接加成(1002) + CharacterGrowth换算(1)) × 星魂套装百分比

直接数值加成 = 装备 + 星魂 + 转生 + 宠物

CharacterGrowth 行键 = AttributeType*10 + 职业族(1..4)，value = Σ 行系数 × 对应六维

```

### 2.4 升级经验



- 客户端 `GetMaxExpByLevel(Lv) = (int)(0.01 * Lv³)`（HotfixView 反汇编确认，经验条上限）。

- 服务端用 **100 倍定点整数**判定，推送 `NumericType.Exp(1027)` 时再除以 100：



  ```

  expNeed(Lv) = 100 * ⌊Lv³ / 100⌋        （不设下限，线上 1~4 级门槛就是 0）

  ```



- 唯一线上实测依据 = 2026-09-13 挂机抓包：1 级 0 经验角色每跳固定 24560 显示经验，

  第 1/2/3/4 跳后分别是 56/67/74/79 级、余 868/264/757/3348。三个候选公式中只有

  `⌊Lv³/100⌋` 且不设下限同时命中这 4 点（`round()` 每点偏大，Lv56 偏 24；

  `max(1, …)` 每点偏大 4）。见 `server-mysql/client_consistency_test.go::TestOnlineCaptureExperienceCurve`。

- 打怪经验 = 线上 `MonsterBase.Exp`（10001 荷叶球 336），与升级阈值无关。

- 主城挂机经验另有固定 24560/分钟一跳，见 21 文档 §5。

> `ET.NumericType` 这个成员名 `Dvo` 容易误导，客户端自己的另一张表说得很明确：

>

> | 来源 | 19 号槽位 | 映射 |

> | --- | --- | --- |

> | `ET.NumericType`（Unity.Model.dll） | 成员名 `Dvo` | `Dvo = 1017` |

> | `Cal.AttributeType`（Hotfix.dll） | **`辅助值`** | 服务端 `gemKeyToNumeric[19] = 1017` |

> | `EquipBase` 字段 | `Dvo` | `equipFieldToNumeric["Dvo"] = 1017` |

> | 客户端装备 tooltip | **`辅助值:{0:p2}`** | tooltip 的 23 个标签正好覆盖 `AttributeType` 1–23，最后一项就是这个槽 |

> 当辅助值（治疗加成）完全合理；**服务端**把它读成治疗加成（`battle_treatment.go` 的

> `CombatAttributeAuxiliary → 1017`），行为合理。

>

> **客户端枚举里没有"闪避"这个成员**，服务端也没有任何闪避判定（无 `CombatAttributeDodge`）。

> 攻击命中走的是「命中(1032) vs 抵抗(1033)」，与闪避无关。

>

> 命中/抗性/辅助值在**战斗中各自在哪些地方生效**，见

> [33-属性对抗与状态命中判定](33-属性对抗与状态命中判定.md)。







## 3. 装备属性并入（EquipBase.json → NumericType）



### 3.1 字段映射（equipFieldToNumeric）



```

Hp→1002(MaxHp) Mp→1004(MaxMp) Str→1005 Quk→1006 Spi→1007 Wim→1008

PhyAtk→1009 SpiAtk→1010 PhyDef→1011 SpiDef→1012

Pcrir→1013 Mcrir→1014 Pcri→1015 Mcri→1016 Dvo→1017

Rpcrir→1018 Rpcri→1019 Rmcrir→1020 Rmcri→1021 Nphyi→1022 Nmeni→1023

Spd→1031 Hit→1032 Res→1033 Phy→1034 Sta→1035

SuckR→1042 SuckV→1043 HpRecover→1044 PhyDA→1045 MicDA→1046

```



### 3.2 最终属性



```

最终值 = 六维基值⌈阶段等级/10⌉ + 手动加点(strAdd/qukAdd/spiAdd/wimAdd)

       + 直接数值加成（装备 + 星魂 + 转生 + 宠物）

       + CharacterGrowth 换算（AttributeType*10+职业族 → Σ 系数×六维）

MaxHp/MaxMp 再乘星魂套装百分比

```



见 §2.3。穿戴/脱下后服务器重推 12 条 20169 + 20025 SendUnitInfo。



> ⚠ **血蓝不再按满值回充**：`pushPlayerAttrsTo` 推的是**当前**血蓝（`battleHP()/battleMP()`）。

> 当前血蓝自 2026-09-13（commit `346e280`）起落在 `players.current_hp/current_mp`，

> 登录只做「超过上限才钳到上限」的裁剪，**不补满**（`playerdata.go` `loadData`）。



### 3.3 EquipTransMessage.mainAttribute



= `List<AttributeMap>{Key=NumericType, Value=float}`，由 EquipBase 主属性字段生成

（血/蓝/六维/攻防/暴击/辅助值等字段按序输出；注意 `Dvo` 是**辅助值**不是闪避，见 §2.5 的命名更正）。当前实例还会编码强化星级、品质、主属性增量、

随机词缀、附加属性和 `GemList`；最终属性计算会把这些实例属性一并加入，重登后保持。

### 4.2 关键实现细节



- **手工 List 字段**：`M2C_GetBag.BagMapList(1)`、`M2C_GetCharacter.WornBagMapList(3)`、

  `M2C_PutOn/M2C_Takeoff.BagMapList(1)+WornBagMapList(2)`、`M2C_UseGoods.BagMapList(1)`——

  先 `proto.Marshal` 基础消息（RpcId/Error/Message/UnitCharacter），再逐项追加 LEN 字段。

- **putOn 校验**：物品存在 + ItemType==1 + JobId 匹配 + UseLevel ≤ 等级 + 槽位有效；

  同部位旧装备先脱下回背包空位。

- **takeoff**：槽位装备回背包空位；背包满返回错误。

- **useGoods**：按 GoodsBase EffectType/FixedHp/FixedMp/持续时间执行回血、回蓝、货币、经验、

  经验卡、魔法球和跑图卡等效果，消耗后推背包/快捷栏/属性或 20080 状态。

## 6. 当前边界（2026-08-17）



- 背包固定 48 格。购买、打造、邮件领取、脱装备等需要新格子的操作在满包时原子拒绝，

  不扣款、不耗材料、不改领取状态；试炼已完成的胜利不会因物品放不下而回滚。

- 拖出丢弃依赖当前 `client-test` 的 HotfixView 补丁接通客户端原有 20263 协议；原始未补丁 DLL

  的拖拽结束分支不会发送该请求。

- 客户端提交任务时把 `m_RewardList.GetSelection()` 原样写入

  `C2M_CompleteTask.IndexList`，但交付按钮没有按 `TaskBase.RwardCount` 阻止空选择；实机会发送空列表。

  服务端与原任务流程一致，不读取 `IndexList`，完成任务时发放 `RewardArr` 中全部可入包物品。因此

  10011 空列表提交会正常完成并发放 6 项配置奖励，不再产生 RPC 错误或“掉线”表现。

- 最新实现和完整验证状态见 [21-当前真实实现与回归基线](21-当前真实实现与回归基线.md)。
