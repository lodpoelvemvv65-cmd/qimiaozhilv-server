## 核心结论速览

1. **传输层：TCP**（⚠ 早期 KCP/UDP 分析已过时，见 02/04/07 文档）。反汇编实证：
   - 客户端 `NetKcpComponentAwakeSystem.Awake`（Unity.Model.dll Rva=0xE17C）`newobj ET.TService::.ctor`
     —— **TService = TCP 传输**；`KService`（KCP）/`KChannel` 类虽存在于程序集但**未被使用**。
   - 服务器 `server/tcp_srv.go`：`net.Listen("tcp", :7756)`。
2. **帧格式（现行）**：`[u16 LE 总长度(含 opcode)][u16 LE opcode][protobuf body]`（PacketParser TCP 变体分帧，
   见 `server/msg.go` packOuter/parseOuter）。**无 KCP SYN/ACK/FIN/MSG 握手，无 conv 改写。**
3. **消息体格式**：
   - Outer（客户端↔服务器）：`[u16 opcode LE][protobuf body]`（RpcId tag=90；ActorId tag=93）
   - Inner（服务器间，未用）：`[i64 ActorId LE][u16 opcode LE][protobuf body]`
4. **序列化规则**：opcode < 40000 → protobuf；40000 ≤ opcode < 51000 → JSON(UTF-8)；否则抛异常。
5. **登录链路**：C2R_Login(20008)→R2C_Login(20009)→C2G_LoginGate(20014)→G2C_LoginGate(20015)→C2G_EnterGame(20027)→G2C_EnterGame(20028)。
   RpcId 字段 tag=90，请求与响应配对。
6. **服务器地址重定向**：`resources.assets` 补丁 `isLocal:false`→`isLocal:true`，客户端改连 `127.0.0.1:7756`。
7. **数据存储**：**MySQL**（玩家/账号/业务状态用规范化表）+ **Redis**（登录与在线缓存、配置通知）。
   运行配置从 MySQL `game_config_nodes` 加载。
   ⚠ 早期写的「SQLite（`modernc.org/sqlite` 纯 Go 驱动）+ `accounts`/`players` 两张表」是旧 `server/`
   实现，已退役；迁移方案见 24 文档（**已实施**），当前实现见 21 文档。

> ⚠ 历史说明：早期分析曾依据程序集中的 `KService`/`KChannel`/kcp.dll P/Invoke 推断传输为 UDP+KCP
> （02/04/07 文档即为此产物）。经反汇编 `NetKcpComponentAwakeSystem.Awake` 实证，客户端实际创建的是
> **TService（TCP）**，早期 UDP/KCP 结论作废，一切以本文档「当前运行状态」与 `server/tcp_srv.go` 为准。
