## 1. 为什么选 SQLite

| 方案 | 结论 |
|------|------|
| SQLite | ✅ **采用**。单文件 `server/data/mhq.db`，`database/sql` + modernc 驱动即可，部署零依赖 |
| MySQL | ❌ 需要安装服务、建库建账号，联调期准备工作多；单服自建联机用不上 |
| 内存+JSON | ❌ 重启丢数据；仅用于最初期验证时可选（见 §6 兜底） |

## 3. 数据模型

两张核心表：`accounts`（账号）与 `players`（角色）。登录三连的字段全部落在上面：

```
accounts
  └─ 1:N ─ players（一个账号可建多个角色，客户端按 PlayerId 选择）
```

### 3.1 accounts — 账号表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK AUTOINCREMENT | 账号内部 Id |
| account | TEXT UNIQUE NOT NULL | 登录账号（C2R_Login.Account） |
| password | TEXT NOT NULL | 密码（明文 or 简单哈希，自建服先明文，见 §5） |
| create_time | INTEGER | 注册时间（Unix 毫秒） |

### 3.2 players — 角色表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK AUTOINCREMENT | 角色内部 Id |
| account_id | INTEGER NOT NULL REFERENCES accounts(id) | 所属账号 |
| name | TEXT | 角色名（C2R_CreateRole.Name） |
| job_id | INTEGER | 职业 Id（C2R_CreateRole.JobId / G2C_LoginGate.JobId） |
| skin_id | INTEGER | 皮肤 Id（G2C_LoginGate.SkinId / G2C_EnterGame.SkinId） |
| level | INTEGER DEFAULT 1 | 等级（后续业务可扩展） |
| last_login | INTEGER | 最后登录时间（Unix 毫秒） |
| is_online | INTEGER DEFAULT 0 | 在线标记（G2C_EnterGame.IsOnline 回 0/1） |

> `player_id`（对外返回的 PlayerId / G2C_LoginGate.PlayerId）直接复用 `id`。
> 服务器启动时生成玩家会话缓存，玩家下线或服务器关闭时写回。

现行 `players.auto_battle` 为 `INTEGER NOT NULL`：`0` 表示关闭，`1` 表示开启，并与
`auto_skills`（自动释放技能列表）分开持久化。旧数据库迁移时临时默认 `-1`，首次加载按旧版本
“自动技能列表非空即显示开启”的语义转换成 `0/1` 并立即保存；以后重启服务或进入下一场战斗都保留开关。

## 4. 建表 SQL

```sql
CREATE TABLE IF NOT EXISTS accounts (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    account     TEXT UNIQUE NOT NULL,
    password    TEXT NOT NULL,
    create_time INTEGER NOT NULL
);

CREATE TABLE IF NOT EXISTS players (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    account_id  INTEGER NOT NULL REFERENCES accounts(id),
    name        TEXT,
    job_id      INTEGER,
    skin_id     INTEGER,
    level       INTEGER DEFAULT 1,
    last_login  INTEGER,
    is_online   INTEGER DEFAULT 0
);

CREATE INDEX IF NOT EXISTS idx_players_account ON players(account_id);
```

## 5. 登录流程与数据库的映射

```
C2R_Login(20008)         → SELECT * FROM accounts WHERE account=? [AND password=?]
   ├─ 不存在 → 回 Error（或引导去 C2R_Regist 注册）
   └─ 存在   → 生成 Key(int64) 存内存会话表 → 回 R2C_Login{Address,Key,GateId}

C2R_Regist(20010)        → INSERT INTO accounts(account,password,create_time)
                            → 回 R2C_Regist（同 R2C_Login）

C2R_CreateRole(20016)    → INSERT INTO players(account_id,name,job_id,skin_id)
                            → 回 R2C_CreateRole

C2G_LoginGate(20014)     → 校验 Key → SELECT * FROM players WHERE account_id=?
                            → 有角色: G2C_LoginGate{PlayerId, HasRole:true, JobId, ServerTime, SkinId}
                            → 无角色: G2C_LoginGate{PlayerId, HasRole:false}

C2G_EnterGame(20027)     → 标记 is_online=1 → 回 G2C_EnterGame{Id, SkinId, JobId, IsOnline:true}
```

- `ServerTime` 用服务器当前 Unix 毫秒（`time.Now().UnixMilli()`），不必落库。
- `HasRole` = 该账号 players 行数 > 0。

## 6. 实现要点（Go）

1. **初始化**：启动时 `sql.Open("sqlite", "data/mhq.db")`，执行建表 SQL（幂等）。
2. **线程安全**：`database/sql` 自带连接池，多 goroutine 并发读写安全。
   SQLite 写锁在并发下会串行，单服玩家量级无压力。
3. **会话缓存**：登录成功生成的 `Key → {AccountId, PlayerId}` 放内存 map（`sync.RWMutex` 保护），
   服务器重启即失效（客户端需重新登录，可接受）。
4. **账号密码**：自建服先明文存储；上线前建议 `crypto/sha256` + 盐。
5. **兜底（可选）**：若想先跑通协议再落库，可先内存 `map[string]*Account` + 定期 dump JSON，
   验证通过后切 SQLite（接口留 `store` 抽象，见 07 §3 项目结构）。
