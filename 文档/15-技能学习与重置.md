# 15 — 技能学习与重置系统（20239-20250 全协议 + 客户端链路 + 服务器实现建议）

> 逆向还原《梦幻奇遇记》技能学习 / 升级 / 自动技能 / 技能重置（免费 + 付费）模块。
> 客户端依据：Hotfix.dll / HotfixView.dll 反汇编（TypeDef RID 已标注，可复现）；
> 数据表依据：`datatable_json/SkillConfig.json`、`SkillLearn.json`、`SkillGroupBase.json`。
> 服务器代码见 **`server-mysql/`**（⚠ 原文写 `server/`，那是已退役的 SQLite 实现；
> 当前唯一服务端是 `server-mysql/`，本节下方的伪代码路径均按此理解）。
>
> **核心结论先行**：
> 1. 技能 ID 是 **6 位数字**（如 `110101`，职业前缀 1/2/3/4，`100001` 为普攻）；
>    SkillConfig/SkillLearn 的 8 位 key = **技能ID × 100 + 等级**（`11010100` 为 0 级元数据行，
>    `11010101..07` 为 1..7 级参数行）。
> 2. 学习/升级走同一条消息 `C2M_LearnSkill(20243){SkillId}`，客户端**双击**技能按钮触发；
>    服务器按当前等级决定是"学习"(0→1) 还是"升级"(L→L+1)，成本查 `SkillLearn`。
> 3. 技能消息**没有独立 Handler 类**（与登录/背包不同），全部在 UI 的 async 状态机内
>    `Session.Call` 直连 await；`M2C_LearnSkill` 响应与 `M2C_GetSkill` 同构（都带
>    SkillInfoLsit + AutoSkillList 字段级 List）。

## 2. 协议表（20238-20250）

> 说明：字段级 List（repeated）在 `protocol_dump.txt` 中不显示，下表已用
> `_dump_prop.py` 补齐（字段 RID：2931/2932/2935/2945/2946）。
> 所有响应统一 `RpcId=90 / Error=91 / Message=92`，请求带 `ActorId=93`。
> **Message 为空 = 成功**；非空 = 失败文案（客户端弹提示框）。

| opcode | 消息 | 字段 tag / 类型 | 方向 | 说明 |
|--------|------|-----------------|------|------|
| 20238 | `ET.SkillInfo`（子消息） | `SkillId=1:int`、`SkillLevel=2:int` | — | 技能条目：6 位技能ID + 当前等级（未学为 0） |
| 20239 | `C2M_GetSkill` | — | C→M | 拉取我的技能列表（无参） |
| 20240 | `M2C_GetSkill` | **`SkillInfoLsit=1:repeated SkillInfo`**（字段级，注意原版拼写 Lsit）、**`AutoSkillList=2:repeated int32`** | M→C | 技能列表 + 自动技能槽列表（6 位技能ID） |
| 20241 | `C2M_SaveAutoSkill` | **`AutoSkillList=1:repeated int32`** | C→M | 保存自动技能槽（客户端拖拽后整表上传） |
| 20242 | `M2C_SaveAutoSkill` | — | M→C | 保存结果 |
| 20243 | `C2M_LearnSkill` | `SkillId=1:int` | C→M | 学习/升级（**同一个消息**，双击技能按钮） |
| 20244 | `M2C_LearnSkill` | **`SkillInfoLsit=1:repeated SkillInfo`**、**`AutoSkillList=2:repeated int32`** | M→C | 响应与 M2C_GetSkill 同构（客户端当前版本未读取，仅检查 Message） |
| 20245 | `C2M_FreeReSetSkill` | — | C→M | 免费洗点（确认弹窗后发） |
| 20246 | `M2C_FreeReSetSkill` | — | M→C | 结果 |
| 20247 | `C2M_GetReSetSkillPrice` | — | C→M | 查询付费洗点价格 |
| 20248 | `M2C_GetReSetSkillPrice` | `Voucher=1:int` | M→C | 付费洗点价格（单位：代金券） |
| 20249 | `C2M_ReSetSkill` | — | C→M | 付费洗点（确认弹窗后发） |
| 20250 | `M2C_ReSetSkill` | — | M→C | 结果 |

编码注意：
- `SkillInfoLsit` 为 repeated message（wire type 2，tag = 0x0A），每元素
  `SkillId`（varint，tag 0x08）+ `SkillLevel`（varint，tag 0x10）。
- `AutoSkillList` 为 repeated int32，推荐 packed（tag = 0x12，wire type 2），
  标准 protobuf 客户端兼容 unpacked 与 packed 两种形式。
- 20240/20244 里客户端字段名是 `SkillInfoLsit`（线上拼写错误），服务端实现
  只按 tag 编码，无需在意名字。

### 3.7 客户端行为小结（服务器必须配合的点）

- **没有** `M2C_GetSkillHandler / M2C_LearnSkillHandler / M2C_SaveAutoSkillHandler /
  M2C_FreeReSetSkillHandler / M2C_GetReSetSkillPriceHandler / M2C_ReSetSkillHandler`。
  这 6 组消息全部由 UI 内 async 状态机 `Session.Call` 直连处理；若服务器不响应，
  客户端 `await` 永不返回 → 技能界面卡死（与文档 09 §4 的 20396 卡死同源）。
- 成功时客户端**不主动刷新**：技能树数据在下次打开界面时重新 `GetSkill`。
- 服务器应在 `M2C_LearnSkill` 里照填 `SkillInfoLsit` + `AutoSkillList`（客户端当前版本
  忽略，但协议同构、未来/其他客户端可能使用）。
- 洗点响应无数据字段，客户端只认 Message。

## 4. 相关数据表结构与字段语义

### 4.1 SkillConfig.json（538 行）—— 技能定义与等级参数

- 8 位 key = `技能ID×100 + 等级`；6 位技能ID 按职业前缀：
  `1xxx=军官(Officer)`、`2xxx=运动员(Sportsman)`、`3xxx=护士(Nurse)`、`4xxx=超能力(Superman)`、
  `5xxx=怪物/宠物`。每职业 22 个技能（含 100001 普攻）。
- **xx00 主体行（技能ID×100）** —— 战斗元数据：
  `_id, Name, Desc, CD(毫秒), CastType(0=无消耗,1=消耗精力,2=消耗血量), CastValue(float),
   PreSkillId(6位前置技能, 0=无), MaxLevel, EffectId, DelayTime, HurtEffectId, Icon[, SkillType]`
- **PreSkillId = 技能解锁链**（已实测）。每个技能指向它的前置：军官
  `100001(普攻,MaxLevel 1) → 110101(7) → 110201(6) → 110301(5) → 110401(5) → 110501(4) →
  110601(3)`，各阶还按分支继续（110202/110302/… 的前置同样是上一阶）。
  规则是**前置技能必须学满到它自己的 MaxLevel** 才能学依赖它的下一个技能；
  只学过 1 级不算（旧实现只判断"学过"，属于 bug）。
- **MaxLevel（xx00 行）** = 该技能等级上限，同时也是 `SkillLearn` 有效行数
  （`xx00..xx(MaxLevel-1)`，`xx(maxLevel)` 那一行永远不会被消耗）。
- **xxNN（NN≥1）等级参数行** —— `_id, Desc(等级描述), MaxLevel(冗余), Args0..Args13(等级参数)`
  （Args 语义因技能而异，通常 Args0=目标数、Args1=伤害/加成百分比、Args2+=附加 buff 参数）。
- **LearnLevel（学习等级门槛）** —— 仅 16 行带该字段：`12020101..04`、`22020101..04`、
  `32020101..04`、`42020101..04`（四职业各一个技能的 1..4 级参数行），值依次
  `1 / 6001 / 13001 / 21501`。⚠ 推断/未证实：疑似"转生×10000 + 等级"门槛。
  OpenSkilUI 下一级预览读取 `next.LearnLevel`（见 §3.3）。

示例：

```json
[11010100, {"_id":11010100,"Name":"爆炸汽油弹","Desc":"军官入门技能...","CD":5500,
  "CastType":1,"CastValue":0.02,"PreSkillId":100001,"MaxLevel":7,"EffectId":2103,
  "DelayTime":1000,"HurtEffectId":2104,"Icon":"11010100"}]
[11010101, {"_id":11010101,"Desc":"1：对2个敌方单位造成112%物理攻击加成的物理伤害。",
  "MaxLevel":1,"Args0":2,"Args1":112}]
[11010107, {"_id":11010107,"Desc":"7：对2个敌方单位造成125%...","MaxLevel":7,
  "Args0":2,"Args1":125,"Args2":22,"Args3":7}]
[10000100, {"_id":10000100,"Name":"普通攻击","CD":5000,"CastType":0,"CastValue":0,

```

### 4.2 SkillLearn.json（488 行）—— 已学技能升级成本

- key 与 SkillConfig 同构（`技能ID×100+等级`）；只有 `_id` + `MaterialArr` 两个字段。
- `MaterialArr[] = { _Id(材料ID), Count(数量) }` —— **技能已经学会后，继续升级消耗的技能书**。
  材料即 MaterialBase 中的"技能秘籍/典籍/上古卷轴"：
  - 20217/20221/20225 = 军官（秘籍/典籍/上古卷轴，品质 2/3/4）
  - 20219/20223/20227 = 运动员；20216/20220/20224 = 护士；20218/20222/20226 = 超能力
- 已由服务端逻辑和真实 TCP 验证：每升一级（含第一次学习）都扣 1 技能点，
  从当前等级 L 升到 L+1 时查 `技能ID×100+L`。例如 1→2 使用后缀 01。
  首次学习（0→1）查 `SkillLearn[xx00]` 行，该行的 MaterialArr 也要扣。
  每技能的行覆盖到 MaxLevel；末尾无法再升级的行不会被消耗。
- `100001`（普攻）没有任何 SkillLearn 行 —— 初始自带，不可学。

示例：

```json
[11010100, {"_id":11010100,"MaterialArr":[{"_t":"SkillLearn+Material","_Id":20217,"Count":1}]}]
[11010106, {"_id":11010106,"MaterialArr":[{"_t":"SkillLearn+Material","_Id":20217,"Count":2}]}]
[11010107, {"_id":11010107,"MaterialArr":[{"_t":"SkillLearn+Material","_Id":20217,"Count":3}]}]
[12020104, {"_id":12020104,"MaterialArr":[{"_t":"SkillLearn+Material","_Id":20225,"Count":40}]}]
```

### 4.3 SkillGroupBase.json（47 行）—— 怪物技能组（与玩家学习无关）

- `_id`(组ID) + `SkillsArr[{Skills_Id}]`；Skills_Id 都是 `500xxx` 怪物技能
  （SkillConfig 前缀 5000，如 500001 波波弹）。重复出现 = 概率权重。
- 战斗用途：MonsterBase.SkillGroupId → 取 SkillsArr[0] 作怪物攻击技能（见文档 09）。

### 4.4 相关属性/货币

- **技能点 SkillPoint**：`UnitCharacter` 属性 index 10（见文档 11），经
  `M2C_GetCharacter(20252)/M2C_SendCharacter(20257)` 同步。**每升一级扣 1 点**：
  升到 L 级共投入 L 点（首次学习 1 点 + 之后每级 1 点），技能书按当前等级行另扣。
  洗点按投入的点数全额返还，付费洗点价格也是这个点数（单位代金券）。
- **代金券 Voucher**：GoodsBase `110204`（绑定货币，"代金券"）—— 付费洗点价格单位。
- 学习材料（20216-20227）走背包物品体系（MaterialBase，MaterialType=1）。

```go
need := SkillLearn[skillId*100+cur].MaterialArr  // 当前等级行；0→1 查 xx00，1→2 查 xx01

扣材料并推 M2C_SendBag

// 4. 写等级
skills[skillId] = cur + 1
// 5. 回包（与 GetSkill 同构）
```


### 5.8 通用约定

- 业务失败：保持 `Error=0`，`Message` 填客户端可显示文案（客户端弹框，避免断线）；
  成功：`Message` 留空（**关键**，客户端以 Message 空/非空判断成败）。
- 学习/洗点后背包变化走已有背包推送（M2C_SendBag / 文档 11），技能数据本身
  客户端重开界面拉取，无需额外推送。
- 学习消息不区分"学习/升级"：服务器按 `cur` 判定，天然支持客户端连续双击连升。

## 6. 验证要点（可用协议脚本断言）

1. **GetSkill 全量返回**：发 20239 空请求，断言 20240 的 `SkillInfoLsit`（tag 1，
   每元素 SkillId tag1 + SkillLevel tag2）包含本职业全部 22 个技能（4 职业各 22；
   普攻 100001 在内），未学技能 SkillLevel=0；`AutoSkillList`（tag 2）与上次保存一致。
2. **学习**：发 `C2M_LearnSkill{SkillId=110101}`，断言 20244 返回的
   `SkillInfoLsit` 中 110101 等级变为 1；再发一次 → 2；发到 MaxLevel(7) 后再发 →
   Error/Message 非空（"已达最高等级"）。
3. **前置校验（学满才解锁）**：`PreSkillId` 是一条解锁链，例如军官
   100001 普攻(MaxLevel 1) → 110101 爆炸汽油弹(MaxLevel 7) → 110201 强化攻击(MaxLevel 6)。
   直接学 110201 → 失败（"请先学习前置技能"）；110101 只有 1 级时学 110201 → 失败
   （"请先把爆炸汽油弹学满"）且不扣技能点、不扣秘籍；把 110101 学到 7 级后学 110201 → 成功。
4. **成本扣减**：每次双击（学习或升级）都扣 1 技能点和当前等级行的技能书：
   0→1 扣 1 点 + `SkillLearn[11010100]` 的书，1→2 再扣 1 点 + `SkillLearn[11010101]` 的书。
   技能点为 0 时即使技能书管够也必须失败（Message="技能点不足"）；
   材料或技能点不足时等级、技能点、背包都不变。
5. **Message 语义**：所有成功响应 Message 必须为空串；失败必须非空。
6. **自动技能**：发 `C2M_SaveAutoSkill{AutoSkillList=[110101,110201,...]}`（须已学）→
   成功；含未学技能 → 失败；重新 GetSkill 断言 AutoSkillList 回读一致。
7. **免费洗点**：学几个技能后发 20245 → 20246 成功；再 GetSkill 断言只保留普通攻击、
   逐级投入的技能点全额返还（等级 L 返还 L 点），技能书不返还，自动技能清空。
8. **付费洗点**：发 20247 → 断言 Voucher 等于已投入技能点（各技能等级之和）；代金券不足发 20249 →
   失败；充足 → 成功且代金券扣减、技能清零、技能点返还。
9. **编码**：用抓包/自写编码器校验 20240/20244 的字段级 List：
   `SkillInfoLsit` = tag 0x0A 拼接的嵌套 message；`AutoSkillList` = tag 0x12 packed varint。
