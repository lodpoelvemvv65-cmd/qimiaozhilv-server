## 1. ★ 原版面板的基础值 = `MonsterBase × 1.53`

把 5 阶家族BOSS 50005 的 `20170` 全部解出来，取**第一次推送**（t=72.5s，战斗刚开始）作为基础值：

| NumericType | 字段 | `MonsterBase` 表值 | 原版面板 | 比值 |
|-------------|------|-------------------|----------|------|
| 1002 | 最大HP | 2,000,000,000 | 2,000,000,000 | **1.000** |
| 1009 | 物攻 | 2,400,000 | 3,672,000 | **1.530** |
| 1010 | 魔攻 | 2,400,000 | 3,672,000 | **1.530** |
| **1011** | **物防** | **2,097,080** | **3,208,532** | **1.530** |
| **1012** | **精神防御** | **1,689,811** | **2,585,411** | **1.530** |
| 1013 / 1014 | 物暴率 / 魔暴率 | 1.3 | 1.989 | **1.530** |
| 1015 / 1016 | 物暴值 / 魔暴值 | 1.5 | 2.295 | **1.530** |
| 1017 | 辅助值 | 2 | 3.06 | **1.530** |
| 1018 | 抗物暴系数 | 2.4 | 3.672 | **1.530** |

| **1022 / 1023** | **物免伤 / 魔免伤** | **0.95** | **0.95** | **1.000** |

**两条硬结论：**
1. **13 个已观测、会缩放的「战斗属性」都乘同一个常数 1.53**：攻击 2、防御 2、暴击率 2、暴击值 2、辅助 1、抗暴 4。HP 与两项免伤另列为不缩放。
2. **HP 和免伤（`Nphyi`/`Nmeni`）不乘**，保持 1.000。

这里的“13 项会缩放”只指**开场倍率**。单流 139 个 BOSS `20170` 中有 75 个纯 tick 帧，字段永远恰好是
`(1009,1010,1011,1012)`；`1013~1021` 除首帧外均不随 tick 增长（仅 `1018` 另有一次独立变化）。
因此战斗内叠层集合是 **4 项**，不是 13 项。

> ⚠ **2026-09-19 更正（本轮独立复算发现）**：本表 1018 原来写的是 `2.4 → 3.312（比值 1.380）`，**那是误读**。
> 独立重算（`tools/_cap39_recheck_C.py`）显示：`1018` 在 BOSS 的 `20170` 里**只出现 2 次**——
> `t=72.49 → 3.672`（战斗开场，= 2.4 × 1.53）、`t=188.80 → 3.312`（**战斗中途的一次变化，−0.36**）；
> 另有 `t=202.79` 经 **`20169` 单推**变回 `3.672`。
> **⇒ `1018` 的基准值就是 3.672（×1.53），3.312 只是 188.80s 的一次战斗内波动，本表没有例外。**
> 上表已改正。误读来源是旧脚本用 `seen.setdefault(类型, 值)` 逐帧取"第一次出现"，
> 而 `20170` 是**增量列表**（见 §2.1 与 `文档/40` §4），这种写法会丢信息。

> **2026-09-19 取整更正**：`2,097,080 × 1.53 = 3,208,532.4` → 面板 **3,208,532**，
> 这一例截断和四舍五入结果相同，不能用于判别。`1,689,811 × 1.53 = 2,585,410.83` →
> 抓包首帧 **2,585,411**，可以确定整数开场属性使用**四舍五入**，不是截断。

#### 2.1.1 ★ 补充（2026-09-18 第二轮，**2026-09-19 更正三处**）：叠层的驱动、节拍、上限、清零

原文只写了"每约 5 秒 +1 层"。第二轮把机制定死了（详见 `文档/43` §2），
**第三轮独立复算又更正了其中三处**（标 ⚠ 的行）：

| 项 | 实测 |
|----|------|
| ⚠ **驱动** | **落在 `4.71 秒` 时间网格上，不是"每次施法"**。BOSS 62 次施法确实多数落在同一格点上，但**11 个格点被跳空时层数照样 +1**（86.90 / 96.31 / 101.02 / 143.38 / 166.91… 这些时刻根本没有 `20075`）⇒ 复算的 92 个物攻变化点里有 **30 个同刻没有 BOSS 施法**。抓包不能直接证明内部就是独立定时器；照抄"每次施法 +1 层"会在跳过回合漏层 |
| **节拍** | **4.71 秒**（不是 5 秒），稳定在 4.706~4.710s；施法间隔直方图 `4.70×1 / 4.71×50 / 9.41×6 / 9.42×1 / 14.12×3`（整拍跳过） |
| **公式** | 只对 `1009~1012` 叠层。令属性 `a` 的开场基线 `B_a = Round(MonsterBase_a × 1.53)`，则 **`面板_a = B_a × (1 + CharacterAdd × n_a − Σd_a)`**；`n_a` 是该属性自己的层数。减益与层数加法叠加、不是相乘：<br>`3,672,000 × (1 + 0.33 − 0.30) = 3,782,160`（实测精确吻合，物攻 1 层 + 玩家 −30%）<br>⚠ **`Σd_a` 不只 −30%**：物防上另有 **−25% / −28% / −58%**（比值 0.75 / 0.72 / 0.42），详见 `文档/43` §2③ |
| **上限** | 观测到最高 **n = 14**（`3,672,000 × 5.62 = 20,636,640`，实测精确吻合）。**这是最长观测段而不是硬上限**：139.03s→204.56s 共 65.53s ÷ 4.71 = 13.9 拍 |
| ⚠ **清零触发** | ✅ **2026-09-19 已定**：只清零该 modifier 实际触及属性的 `n_a`。`210603 开大脚` 命中及 14.0s 到期会清物攻/物防，但精神防御继续累计；持续期内刷新不清零。完整证据见 `文档/43` §2④ |

> 上表第 2 行那句"×0.70 是被玩家 -30% 削"在这一版得到了更精确的解释：
> **-30% 削的是战斗开场基线 `B` 的比例，和 `CharacterAdd×n` 加在同一括号内**，不是乘在叠层后的总值上。

## 4. 防御在伤害公式里的位置（旁证）

抓包里玩家的 `物防` 是 7.1e5 ~ 1.8e6，而 BOSS 的 `物防` 是 3.2e6 ~ 5.3e6：

- 玩家 22233 的 `物攻 = 2.12e6` < BOSS 物防 3.2e6 ⇒ `base = atk − def < 0`
  ⇒ 按我们的公式会被夹到 1 ⇒ 伤害 = `1 × 技能百分比`
- **抓包里确实反复出现 `伤害 = 1` 的帧** ✓ 这与「最小伤害夹到 1」一致，
  **说明线上的伤害公式也有「减防后小于 1 就取 1」这一步**（doc 34 记录的公式形状得到旁证）

> 另外注意到一个有趣现象：伤害值 `4,967,942` 同时出现在 **BOSS 身上 16 次**和 **玩家 22235 身上 4 次**
> —— 那是 BOSS 的 `500032 打我试试`（**反伤 100%**）把玩家对它的伤害原样弹回去了 ✓
> 这也间接验证了反伤 = 「按实际伤害的百分比反弹」。
>
> **2026-09-18 复核成立**：`248.97s` 与 `277.97s` 两个时刻，BOSS 与玩家 22235 **在同一拍**各扣 `4,967,942`
> （同一时间戳、同一数值），确实是原样弹回 —— 不只是"数值恰好相同"。
