## 1. 现场问题

本次需要处理的现象共有六项，另有一项在全量审计中发现：

1. 主线自动战斗看起来无法继续。
2. 当前层还没有打怪时已经出现传送阵，可以直接进入下一层；进入下一层后又可能无法开战。
3. 高等级、高属性队员仍然很快死亡。
4. 界面显示的角色等级不正确。
5. 组队头像中的血量不正确。
6.（补充）还有一个问题就是在我的血量和蓝量是8e，1e时候，然后换一个形象，这个形象，我服务端调整了他的上限，属性极限了，然后会回到客户端的极限的，服用紫药，第一次服用会导致生命为0，第二次才正常回满，这个是在本地发现的问题
这六项不是同一个故障，但彼此会形成连续表现：未清怪进入下一层后开始战斗，怪物集中攻击一个队员，将其服务端真实 HP 打到 0；下一场战斗因队伍中存在死亡成员而拒绝开始。与此同时，队伍栏的 HP 和等级没有在重建后完整刷新，画面显示又与服务端状态不一致，因此最终看起来像“自动跑图失效、明明血很多却不能打”。第七项则是独立的战斗命中率换算问题。

## 3. 已确认的根因

### 3.1 主线传送门只对海滩做了通关限制

当前 `server-mysql/map_transition.go` 中只有海滩 `10006xx` 使用以下专用逻辑：

- `beachTransferPointUnlocked`
- `scheduleBeachTransferPoint`
- `beachHighestCompletedLayer`
- `markBeachLayerVictory`

`finishMapStartupWithOptions` 对海滩以外的地图会立即推送：

```text
M2C_StartupTransPoint (20039)
```

`onRequestEnterMap` 也只在海滩相邻层跳转时检查是否已经胜利。其他 `MainStory` 地图只要目标 `SceneId` 存在于场景配置中，就可能被 `validMapTransition` 接受。

远端日志与代码一致：服务端在进入 `1002603` 时直接下发传送点，客户端也会在场景加载后立即发送下一层请求。由此确认“没打怪就有传送阵并能下层”是服务端缺少通用主线通关门控，而不是客户端单独显示错误。

### 3.2 一波中的所有怪物固定集火同一名队员

当前 `server-mysql/battle_monster_attack.go` 在构造每只怪物的施法时都使用：

```go
primary := battle.runtime.Player()
```

组队战斗共享 `party.monsterReadyAt`。哪一名队员的行动先触发这一轮怪物反击，就由该队员的 `battle.runtime.Player()` 成为整波怪物的主目标。随后循环中的每一只怪物都沿用同一个目标，没有在存活队员之间重新选择。

现场 `region=1163` 对应地图 `1002603`，配置为 10 只 `MonsterBase 10163`：

| 项目 | 数值 |
|---|---:|
| 怪物 | 侯爵猫（物） |
| 等级 | `7700` |
| 单只 HP | `8,972,220` |
| 物理攻击 | `144,444` |
| 技能组 | `10002` |
| 实际攻击技能 | `500003`，单体物理攻击，约 `200%` 攻击倍率 |

服务端会先扣目标物理防御，再应用技能倍率。十只怪物每六秒对同一个人集中攻击，持续约一分钟，足以把该队员打到 0 HP。这个结果与现场远端权威血量完全吻合。

所以“高属性仍扛不住”的主要原因不是属性公式或客户端血条本身，而是组队怪物目标分配错误造成的异常集火。

### 3.3 队伍栏 HP 刷新只处理了当前 HP，且缓存更新条件过窄

已有提交 `2fa9efc` 增加了队伍栏 HP 重放，但当前实现仍有三个缺口：

1. `prepareTeamHeadHPRefresh` 在 `M2C_TeamMember(20162)` 前后只发送 `NumericType=1001`（当前 HP），没有同时重放 `1002`（MaxHP）。新建队伍头像后可能保留模板或旧最大值，导致血条比例错误。
2. `session.teamHeadHP` 只在创建 `UnitCharacter`、完整 Numeric 快照，或“给玩家本人发送本人 HP”时更新。战斗伤害广播给队友时，不一定更新被攻击玩家自己的队伍栏缓存。
3. 组队胜利/失败结算会逐个执行 `syncBattleHealthToSession` 和魔法球恢复，但最终 HP/MaxHP 没有在所有成员完成结算后再向全队广播。因此队友可能继续看到战斗前或战斗中的旧值。

远端现场已经出现“服务端权威 HP 为 0，但队伍栏仍显示旧血量”，说明这是实际发生的显示状态陈旧，不只是理论风险。

### 3.4 等级同步值正确，但队伍栏重建后没有重新触发等级观察器

客户端等级显示使用：

- `NumericType=1026`：累计等级
- `NumericType=1029`：转生次数
- 转生等级起点：`{0, 6000, 13000, 21500, 31500}`

玩家 `3894` 的服务端值为：

```text
Level = 17007
Trans = 2
```

按客户端逻辑应显示为 `2转4007级`（客户端实际符号样式以原界面为准）。服务端 `UnitCharacter.Level` 和 `UnitCharacter.Trans` 的数据本身正确。

已有提交 `413a0e5` 曾通过 `1029 -> 1026(level-1) -> 1026(level)` 强制刷新本人的场景等级观察器，但后续提交 `049acdc` 为匹配原版登录批量快照而移除了这段强制重放。当前完整 Numeric 快照虽然保证 `1029` 排在 `1026` 前面，但普通 `M2C_TeamMember` 重建队伍头像后不会再次发送这两个 Numeric，也不会保证相同值触发新头像的等级观察器。

因此当前等级问题更准确地说是“队伍/场景 UI 重建后的观察器刷新缺口”，不是 MySQL 中保存了错误等级，也不是服务端把累计等级算错。

以下改动应按功能拆分，分别测试、分别提交。

### 4.1 通用 MainStory 通关与传送门门控

建议新增通用主线层完成状态，不再只识别海滩：

1. 用 `(SceneId, Layer)` 从 MySQL 已加载的 `MainStory` 配置树解析当前 `region`。
2. 每次主线胜利时记录当前 `region` 已完成；可以复用 `player_kill_counts` 中不会与线上 MonsterId 冲突的保留 key，保持跨登录持久化。
3. `finishMapStartupWithOptions` 对所有有 `MainStory` 行的地图检查完成状态。未完成当前层时不发送 `M2C_StartupTransPoint`。
4. 胜利包发送完成后，延迟下发当前地图的传送点，沿用现有海滩时序，避免客户端在战斗退出动画中提前触发。
5. `onRequestEnterMap` 做服务端权威校验：当前地图和目标地图都是 `MainStory` 时，只允许原地请求或进入配置上的下一 `region`；进入下一层前必须已完成当前层。
6. 回主城请求继续无条件按现有规则处理，不能被主线门控误伤。
7. 保留并兼容已有 `beachHighestLayerKey` 数据，避免老角色海滩进度倒退。

建议提交信息：

```text
fix: require main-story victory before advancing layers
```

### 4.2 组队怪物目标公平分配

建议为 `partyBattle` 增加确定性的怪物目标游标：

1. 每只敌方怪物施放单体攻击时，从 `party.memberIDs` 中选择下一名仍存活、仍可被攻击的队员。
2. 一波内按轮询方式分配，避免十只怪全部锁定同一人。
3. 下一波从上次游标继续，避免成员排列靠前者长期多承伤。
4. 已死亡、已离队或不可选中的成员必须跳过。
5. 单人战斗继续固定选择本人。
6. 怪物自我/友方技能继续按技能原有 `TeamType` 和目标语义执行，不能错误分配到玩家。
7. 多目标技能仍交给现有 `resolveSkillTargets` 展开，不应因为主目标轮询而丢失合法范围目标。

使用确定性轮询而不是直接随机，便于复现、抓包比对和稳定测试。

建议提交信息：

```text
fix: distribute monster attacks across living party members
```

### 4.3 队伍栏 HP/MaxHP 权威同步

建议把队伍栏生命同步改为一组完整生命快照：

1. `M2C_TeamMember` 重建前后同时重放 `1002 MaxHP` 和 `1001 HP`。
2. 继续保留 HP 的 float32 nudge，确保相同最终值也能触发新建队伍头像的 NumericWatcher。
3. MaxHP 也需要保证在最终 HP 之前送达，避免客户端用旧上限计算百分比。
4. 权威战斗 HP 每次变化时直接更新对应玩家的 `teamHeadHP` 缓存，而不是依赖“该 HP 包刚好发给本人”这一旁路条件。
5. 组队胜利/失败、魔法球自动恢复完成后，统一把每名成员最终的 MaxHP/HP 广播给所有仍在线的参战成员。
6. 不允许为了刷新界面修改 `session.hp` 或 `battle.playerHP`；nudge 只存在于下行展示消息中。

建议提交信息：

```text
fix: synchronize final party health and maximum health
```

### 4.4 队伍栏等级与转生显示刷新

## 8. 补充问题：高抵抗角色几乎不会受到怪物直伤（2026-09-04）

### 8.1 现场复算

现场为达人 4：

| 项目 | 数值 |
|---|---:|
| 地图 | `SceneId=10026`，`region=1164` |
| 怪物 | `MonsterBase 10164` 德古拉伯爵猫（魔） |
| 精神攻击 | `188888` |
| 技能组 | `10005` |
| 攻击技能 | `500017`，200% 精神伤害 |
| 玩家精神防御 | 约 `117394` |
| 理论非暴击直伤 | `(188888-117394)×200%=142988` |

怪物攻击配置、技能组和伤害公式都存在，问题不在“怪物没配攻击”。本地同类高阶角色的面板属性复算为：`Hit≈189.159`、`Res≈6906.254`、物理免伤 `47%`、精神免伤 `40%`，免伤也没有达到 100%。

### 8.2 根因与修复边界

装备、星魂和转生配置中的 `Hit/Res` 以小数比例存储，例如 `0.06=6%`；战斗运行时转换为百分数点。旧代码把玩家已经很高的 `Res` 继续放入怪物直伤命中公式，而 `MonsterBase` 全表没有 `Hit/Res` 字段，怪物命中只能按 0 计算：

```text
100 / (100 + 690625) ≈ 0.014%
```

因此客户端能看到攻击动画，但几乎收不到伤害事件。修复后：

1. 怪物对玩家的直接物理/精神伤害不再执行 Hit/Res 判定，进入正常攻击、防御、倍率、暴击/抗暴和免伤结算。
2. 玩家 `Res` 仍参与怪物有害状态的抵抗，眩晕、沉默、冻结、石化和 DOT 等没有被改成必定施加。
3. 玩家攻击怪物和 PVP 的现有命中机制保持不变，避免扩大协议行为变更。
4. 达人 4 定点回归断言伤害为 `142988`，玩家 HP 从 `1000000` 降至 `857012`。

### 8.3 全地图、全怪物、全属性审计
