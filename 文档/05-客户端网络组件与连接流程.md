# 05 — 客户端网络组件与连接流程

## 1. 组件层级

```
NetThreadComponent (每帧驱动)
  └─ NetKcpComponent ── Instance.Add(Service)
       └─ TService (TCP，newobj ET.TService::.ctor)
            ├─ 客户端: Connect() 建立 TCP 连接
            ├─ 服务端: AcceptAsync/OnAcceptComplete 接受连接
            └─ 通道: TChannel (每连接一个)
```

- 客户端网络栈由 `NetThreadComponent` 的 `LateUpdate` 驱动：遍历所有 `Service` 调 `Update()`。
- 服务器侧等价物：每 channel 一个 KCP 实例 + 单 goroutine 收包循环 + 定时 Update。

## 2. NetKcpComponent 回调整定

`NetKcpComponent.Awake`（2 参）与 `Awake1`（3 参）反汇编确认：

```
Awake(service, 回调...):
    AService 回调注册（Delegate.Combine 链式组合）：
        ReadCallback  += 当前组件 OnRead
        ErrorCallback += 当前组件 OnError
    Service 创建后 Instance.Add(Service)

Awake1(service, 回调..., acceptCallback):
    以上 + AcceptCallback += 当前组件 OnAccept
```

- `OnRead(Id, stream)`：创建/查找 channel 对应的 Session 并投递消息（见下）。
- `OnError(Id, error)`：断开 channel、置空关联 Session。
- `OnAccept(Id, address)`：收到新连接时建立 Session（见 §4）。

## 3. 通道 Id 与 LocalConn 生成（AService）

`AService`（aservice_dump.txt）：

| 方法 | 生成规则 | 用途 |
|------|----------|------|
| `CreateConnectChannelId(id)` | `(--connectIdGenerater) << 32 \| (uint)id` | 主动连接通道 Id，**无 0x40000000 前缀** |
| `CreateAcceptChannelId(id)` | `(++acceptIdGenerater) << 32 \| (uint)id` | 被动接受通道 Id |
| `CreateRandomLocalConn()` | `0x40000000 \| RandUInt32()` | 客户端/服务器各自的 LocalConn |

- `Id` 高 32 位是自增序号，低 32 位是会话 Id；`LocalConn` 是独立随机值（高位置 1）。
- KService.GetOrCreate(Id, address) 内部：`channel = Get(Id)`，无则 `new KChannel(Id, LocalConn=CreateRandomLocalConn(), RemoteConn=0, RemoteAddress, Service)`。

## 4. Session 创建（OnAccept，服务器接受方向）

`NetKcpComponent.OnAccept(Id, address)`：

1. `Session.Create()`：`Id = RandInt64()` 随机生成 Session Id；
2. `Service.GetOrCreate(Id, address)` 建 Accept channel（`ChannelType=1`，
   与客户端 Connect 通道对称：`LocalConn=S` 服务器随机值、`RemoteConn=C` 待 ACK 建立后回填）；
3. 绑定 `RemoteAddress`、设 timeout（反汇编观察值 2000ms，ET RPC 超时）；
4. 注册回调（Read/Error）并挂到 Session。

## 5. 连接建立完整流程（客户端视角）

```
1  LoginHelper 拿到网关地址 (127.0.0.1:7756)
2  NetKcpComponent.Create(serviceType=Outer)
3  AService.CreateConnectChannelId → Id
4  KService.GetOrCreate → KChannel(LocalConn=C, RemoteConn=0)
5  KChannel.Connect():
       WriteTo(cache,0,0x01); WriteTo(cache,1,C); WriteTo(cache,5,0);
       SendTo(cache,0,9,0,RemoteAddress);         // 发 SYN
       每 300ms 重发；10s 超时 → OnError(100205)
6  Session.Call(C2R_Login...) 期间所有 Send 进 sendBuffer 队列（未连接）
7  服务器回 ACK [0x02][S][C]
8  KService.Recv: GetByLocalConn(C) → channel
       set_RemoteConn(S); HandleConnnect()
       → 重建 KCP(conv=S, user=C); InitKcp(); IsConnected=true
       → sendBuffer 队列补发（C2R_Login 发出）
9  Session 收到 R2C_Login → RpcId 配对 → Tcs.SetResult
```

> 关键：**RPC 消息在 ACK 完成前就排队等待**。服务器只需按"ACK 后立刻能收到
> 客户端积压的完整业务消息"来设计，不必在握手阶段特殊等待业务首包。

## 6. 对自建服务器（Go）的含义

1. 服务器不主动建 channel——等客户端 SYN 到达后分配 `LocalConn=S` 并建 accept channel（02 文档时序）。
2. 单 UDP socket 监听，每来一包：按 `cache[0]` 分派 SYN/ACK/FIN/MSG，按 conv/LocalConn 路由。
3. Session 层等价物：channel + 一个逻辑会话（记录登录态、玩家数据）。
4. 服务器 Respond 也是普通 Send：body 里带 `RpcId` 原样回填（06 文档），客户端 Session.OnRead 自动配对。
