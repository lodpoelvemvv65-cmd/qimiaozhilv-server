# 17-宠物系统（opcode 20370–20390）

> 逆向还原《梦幻奇遇记》宠物系统的完整协议与服务器实现依据：消息结构（Hotfix.dll 反汇编 +
> `_dump_prop.py` 字段级 ProtoMember）、客户端 UI 处理链路（HotfixView.dll 反汇编）、原版数据表
> （PetConfig / PetLevelConfig / PetExploreConfig / GoodsBase 宠物粮食）、服务器实现建议（仅文档，
> 不改 `server/` 代码）。
>
> 结论先行：
> 1. **单宠物系统**——每个玩家只有一只宠物，宠物状态存玩家数据，客户端以挂在 MyUnit 上的
>    `ET.Pet` 组件为本地状态源（`PetUI.AwakeAsync` 直接 `MyUnit.GetComponent<Pet>()`）。
> 2. **除 `C2M_UpgradePet{index}` 外，所有 C2M 宠物请求都是零参数**（RpcId/ActorId 除外）：
>    服务器自己决定宠物、当前状态、动作时长与奖励，客户端没有任何时长/档位选择 UI。
> 3. `M2C_SyncPet(20370)` 是唯一的状态推送通道（喂食/升级/开始动作/结束动作后都要推）；
>    `petState` 枚举 0=等待 1=跟随 2=嬉戏 3=锻炼 4=探险（`ET.Pet+PetState`）。
> 4. **关键坑**：`M2C_SyncPetHandler` 里 `UnitComponent.Get(UnitId)` 拿不到单位会静默 NRE
>    （try/catch 吞掉，Log.Error），宠物显示依赖"宠物 Unit 已存在于场景"。
>    线上服务器通过 `M2C_UnitsInMap(20036)` 把宠物作为单位下发；自建服务器可退化为
>    **`UnitId` 直接填玩家自身 UnitId**（MyUnit 一定有 Pet 组件），客户端照样能创建跟随宠物。
> 5. 宠物粮食走既有 `C2M_UseGoods(20275)`：`GoodsBase.EffectType=15`（宠物粮食，`OtherParam`
>    解析 exp/intimacy/active）与 `=16`（经验卡，`ExpRange`×`ContinuedSeconds`）。

### 1.4 服务器侧状态推送全景（客户端视角）

```
喂食/升级/动作开始结束 → 服务器 M2C_SyncPet(20370) 推给本人
    → M2C_SyncPetHandler(Hotfix rid 245) 更新 Unit.Get(UnitId).Pet{petId,name,level,exp,intimacy,isShow}
    → Publish(SwitchPetDisplay) → SwitchPetDisplayEvent(HotfixView rid 81) 创建/移除跟随宠物单位
进图/换图 → 服务器 M2C_ChangeMap(20033) → M2C_ChangeMapHandler
    → MyUnit.GetComponent<Pet>() → Publish(SwitchPetDisplay{unit=MyUnit, isShow=pet.isShow}) 恢复跟随
他人宠物（线上） → M2C_UnitsInMap(20036) 宠物单位(LeaderId=队长) → UnitsInMapHandler
    → 填 Pet 字段(UnitCharacter.PetId/IsShowPet/PetLevel/PetName) → SwitchPetDisplay
```

## 4. 相关数据表结构与字段语义

### 4.1 `PetConfig.json`（宠物基础配置，客户端引用）

```
PetConfig{ _id:long, Name:string, PrefabId:int, UpgradeIdArr:int[], NeedLevel:int,
           NeedIntimacy:int, AddAttibuteMapArr:AddAttibuteMap[] }
AddAttibuteMap{ Key:int(=Cal.AttributeType), BaseValue:float, Value:float }
属性公式（客户端显示，GetAttributeString 确认）：attr(Key) = BaseValue + Value × petLevel
```

示例行（宠物 2101「宠物01」）：
```json
{"_id":2101,"Name":"宠物01","PrefabId":4201,"UpgradeIdArr":[2102,2103],
 "NeedLevel":25,"NeedIntimacy":3271,
 "AddAttibuteMapArr":[{"Key":20,"BaseValue":0,"Value":12},{"Key":21,"BaseValue":0,"Value":12},
                      {"Key":5,"BaseValue":0,"Value":12}]}
```
- 升级链：2101→(2102 或 2103)→(2104)→(2105)；2104/2105 无 UpgradeIdArr（顶阶）。
- 升级条件：`NeedLevel`=当前宠物等级需求、`NeedIntimacy`=亲密度需求（升级面板红/绿显示）。
- PrefabId 4201~4205 = `Sys_Prefab.json` `Assets/Download/Role/RolePrefab/Pet/Pet0X.prefab`。
- Key 为 `Cal.AttributeType` 枚举（Hotfix rid 2），与宠物属性相关的取值：

| Key | 属性 | Key | 属性 | Key | 属性 |
|---|---|---|---|---|---|
| 1 | 最大生命 | 8 | 精神攻击 | 20 | 体质 |
| 2 | 最大精力 | 9 | 物理防御 | 21 | 耐力 |
| 3 | 力量 | 10 | 精神防御 | 22/23 | 物理/精神免伤 |
| 4 | 敏捷 | 11/12 | 物理/精神暴击系数 | 24 | 速度 |
| 5 | 精神 | 13/14 | 物理/精神暴击效果 | 25/26 | 命中/抵抗 |

### 5.4 动作时长与状态机


### 5.5 结算与快速完成

```go
// 正常到点结算（GetPetActionReword 时按已过时长比例结算，或按完整时长）
func petActionRewards(p *PetData) (exp, intimacy int32, items map[int32]int32) {
    cfg := petExploreConfig[p.ActionCfg]
    for _, e := range cfg.EndRewordArr {   // Type1: 按 PetId 的 IncressValue 发物品
        if e.PetId == p.PetId { items[e.IncressValue] = 1 }
    }
    // Type2: IncressValue → intimacy 加值（16~80）
    // Type3: IncressValue → exp 加值（160~800）；若 ExpCard 生效中 exp *= ExpCardMul
}
// 立即完成（EndPetAction）：扣 voucher 后按“完整时长”结算（线上语义）
func quickEndPrice(p *PetData) int32 {
    remain := p.ActionEnd - now()
    // 建议：按剩余时长计价（如 ceil(剩余分钟/10) 张代金券），文档标注为设计取舍
    return int32((remain + 9_999) / 10_000)   // 示例：每 10 秒 1 张
}
```

## 6. 验证要点（可用协议脚本断言）

1. **面板数据（20375/20376）**：登录建号后打开宠物面板 → 收到 `M2C_GetPetInfo`
   `{eatCount=上限值, active=0, petState∈{0,1}, remainTime=0}`；断言 `Message` 为空。
2. **ShowPet 切换（20371→20370）**：发 `C2M_ShowPet{}`（无响应消息）→ 收到 `M2C_SyncPet`
   `isShow=true/false` 交替，且 `UnitId==玩家自身UnitId`（自建方案）或 `UnitsInMap` 中
   宠物单位 `LeaderId==队长`、`UnitCharacter.PetId/PetLevel/IsShowPet` 正确。
3. **喂食（20275→20276+20370）**：背包放 110385 宠物粮食 → 使用 → `M2C_UseGoods` 数量-1，
   随后 `M2C_SyncPet` `exp` 增加 100；用 110390 → `intimacy` +20；110387 → `active` +1 且 exp+500；
   连续喂到超过每日上限 → 20376 `eatCount==0` 且 20275 返回错误。
4. **升级曲线**：喂到 `exp >= needExp(level)` → `M2C_SyncPet.level` 自增、exp 扣减；等级到
   `PetLevelConfig.MaxLevel` 后经验不再增长。
5. **动作（20377/20379/20381→20378/20380/20382）**：依次发三个开始请求 →
   断言 20376 `petState` 依次为 2/4/3 且 `remainTime` 在对应时长区间；已开始动作时重复发
   同/他类开始 → 返回错误（Message 非空，客户端会弹提示）；客户端按钮也会本地禁用（状态检查）。
6. **快速完成（20387→20388 + 20383→20384）**：动作进行中查价 → `voucher>0`；确认后发
   `C2M_EndPetAction{}` → 宠物经验/亲密按完整时长到账（20370 推送），代金券（NumericType 1025）
   扣减；再查 20376 `remainTime==0`、`petState` 回到 1/0。
7. **领奖（20385→20386）**：动作到点后发 → 宠物获得对应收益 + 背包物品（Type1 探险奖励），
   重复领 → 返回错误；未到点领 → 返回错误。
8. **升级（20389→20390）**：level/intimacy 不达标 → 20390 Message 非空；达标后
   `C2M_UpgradePet{index=0}` → 20370 `petId` 变为 `UpgradeIdArr[0]`（2102 或 2103），
   20257/20252 `UnitCharacter.PetId/PetName/PetLevel` 同步更新；index 越界 → 错误。
9. **数值计算**：`attr = BaseValue + Value×level` 与客户端面板显示一致（宠物 2101 Lv1：
   体质/耐力/精神各 12；Lv10：各 120）。
