# 16-邮件系统与聊天系统协议分析

> 目标模块：邮件系统（20279 MailItem / 20280 Mail / 20281-20290 GetMail·ReceiveMail·DeleteMail·ReceiveAllMail·DeleteAllMail）与聊天系统（20298/99 RequestChat、20300 SendNormalChat、20301 SendSystemChat）。
> 分析方法：Hotfix.dll / HotfixView.dll 反汇编（`_disasm.py` / `_disasm_raw.py` / `_dump_prop.py`）+ `protocol_dump.txt` + `datatable_json/*.json`。
> 结论性质：**客户端协议与处理链路的完整还原；服务端实现建议仅写入本文档，本次未改动客户端或 `server-mysql/` 代码。**

---

## 1. 功能概述与入口

### 1.1 邮件系统

- 邮件 UI 是 **FairyGUI 包 `ui://Mail/MailUI`**（包名 `Mail`，组件 `MailUI`/`FrameMailUI`/`ButtonMailItem`）。
- 入口：**主界面（MainUI）的邮件按钮 `m_btnMail`**。点击后：
  1. `MainUI.<AwakeAsync>b__3_3`（HotfixView TypeDef 561 的闭包回调）构造 `ET.EventType.MailUI_Open{ zoneScene = ZoneSceneManagerComponentSystem.ZoneScene }`，通过 `Game.EventSystem.PublishAsync` 发布；
  2. `ET.OpenMailUIEvent.Run`（TypeDef 108）收到事件 → `FUIHelper.Open(zoneScene, "ui://Mail/MailUI", null)`（MD#411）打开 FUI 面板；
  3. `ET.MailUIEvent.OnCreate`（TypeDef 555）`FUIComponent.Instance.Get("ui://Mail/MailUI")` 若不存在则 `CreateInstanceAsync<FUI_MailUI>()` 并 `set_Name("ui://Mail/MailUI")`，随后挂到 FUIComponent；
  4. 旧式包装层 `ET.MailUI`（TypeDef 554，对应 `MailUIAwakeSyatem`/`MailUIDestroySyatem`）`Awake` → `AwakeAsync().Coroutine()`：先 `GetMailAsync` 拉取**第 1 页**邮件，再给列表/按钮挂事件。
- **服务器没有"推送打开邮件 UI"的消息**（protocol_dump 中无 M2C_OpenMailUI），只能由玩家点主界面按钮打开。

### 1.2 聊天系统

- 聊天 UI **没有独立面板**，聊天板内嵌在 **MainUI（主界面 HUD）** 中，相关 FUI 元素：
  `m_chat`（控制器容器）、`m_chatList`（频道 Tab 列表）、`m_chatContentList`（消息虚拟列表）、`m_btnChatReceive`（收/展聊天板）、`m_btnChatSend`（发送）、`m_txtChatType`（当前频道名）、`m_inptChatContent`（输入框）、`m_txtGlobal`（全局提示文本）等（`FUI_MainUI` TypeDef 295 字段）。
- 聊天板控制逻辑在 `ET.MainUI`（TypeDef 561）内的静态字段与方法：
  - 静态字段：`chatType`（当前频道，`ChatType`）、`chatBoardState`（`ChatBoardState`）、`tagetChatId`（私聊目标 Id）、`chatContiator`（懒加载单例）。
  - `InitChatFunction()`：初始化 `ChatContiator`（绑定 `m_chatContentList` 为虚拟列表）、设 `chatType=1`（`ChatType.Normal`）且 `m_chatList.selectedIndex=1`（频道 Tab 高亮与 chatType 对齐）、渲染频道名、绑 `m_chatList.onClickItem`（切频道）、`m_btnChatReceive.onClick`（收/展聊天板）、`m_btnChatSend.onClick` 与 `m_inptChatContent.onSubmit`（发送）。
- 收到聊天消息的链路：`M2C_SendNormalChat` / `M2C_SendSystemChat` → Handler（Hotfix）→ `ChatMessageComponent`（消息缓存）→ 发布 `EventType.AddChatUIText` → `AddChatUITextEvent`（HotfixView）→ 刷新聊天板；当 `IsSystemBrocast=true` 时，同一条正文还会进入 MainUI 的界面中心全局播报队列 `m_txtGlobal`。该控件不是角色头顶聊天气泡。

## 2. 协议表

消息类全部在 Hotfix.dll `ET.` 命名空间；请求均带 `RpcId tag=90`、`ActorId tag=93`；响应带 `Error tag=91`、`Message tag=92`。字段级 List（repeated）字段在 `protocol_dump.txt` 中不显示，已用 `_dump_prop.py` 补齐（表中以 ★ 标注）。

### 2.1 枚举

| 枚举 | 值 |
|---|---|
| `ET.MailState` | `UnReceive=0`（未领取附件/未读）、`Received=1`（已领取） |
| `ET.ChatType` | `NoneChat=0`、`Normal=1`、`Team=2`、`Family=3`、`Camp=4`、`World=5`、`Private=6`、`System=7` |
| `ChatBoardState`（MainUI 内嵌） | `Short=0`（收起）、`High=1`（展开）、`None=2` |

| Opcode | 消息名 | 字段 tag / 类型 | 方向 |
|---|---|---|---|

## 3. 客户端处理链路

### 3.1 邮件 UI（`ET.MailUI`，HotfixView TypeDef 554）关键反汇编解读

`AwakeAsync`（状态机 `<AwakeAsync>d__4`，TypeDef 1115）流程：

```
await GetMailAsync();                       // 拉第 1 页
ui.m_itemList.onClickItem   → b__0         // 点列表项 → 显示邮件详情
ui.m_btnLastPage.onClick    → b__1         // currPage--，若 currPage>0 再 GetMailAsync
ui.m_btnNextPage.onClick    → b__2         // currPage++，若 currPage<totalPage 再 GetMailAsync
ui.m_btnReceive.onClick     → b__3(1334)   // 领取单封（异步）
ui.m_btnDelete.onClick      → b__4         // 删除单封（弹确认）
ui.m_btnReceiveAll.onClick  → b__5         // 一键领取（弹确认）
ui.m_btnDeleteAll.onClick   → b__6(1336)   // 一键删除（异步，无确认）
```

**GetMailAsync（TypeDef 1337）**：
```csharp
var resp = await zoneScene.GetComponent<SessionComponent>().Session
    .Call<M2C_GetMail>(new C2M_GetMail { Page = currPage });   // opcode 20281
if (!StringUtil.IsNullOrEmpty(resp.Message)) { TipHelper.OpenUI(resp.Message); return; }
ShowMailItem(resp.MailList, resp.MailCount);   // MailCount == 总页数
```

**ShowMailItem(List<Mail> mailList, int totalPage)（`<AwakeAsync>g__ShowMailItem|8`）**：
- `this.totalPage = totalPage; ui.m_txtPage.text = string.Format("{0}/{1}", currPage + 1, totalPage);`
- `mailDic.Clear(); ui.m_itemList.RemoveChildrenToPool();` 然后 `foreach (mail in mailList)`：
  - `mailDic[索引 i] = mail`（`mailDic` 是 `Dictionary<long/ int, Mail>`，key = 列表序号；后续 `TryGetValue(selectedIndex, out mail)` 取选中项）；
  - `var item = ui.m_itemList.AddItemFromPool().asButton; var itemUi = GetFormPool<FUI_ButtonMailItem>();`
  - `itemUi.m_txtTitle.text = mail.Title; itemUi.m_txtSenderName.text = mail.SenderName;`
  - `itemUi.m_txtTime.text = (DateTimeOffset.FromUnixTimeMilliseconds(mail.RemainTime).DateTime - DateTime.UtcNow).ToString("dd\\天hh\\时mm\\分")` —— **RemainTime 是绝对到期时间戳（毫秒）**，客户端算剩余时间倒计时；
  - `itemUi.m_Read.SetSelectedIndex(mail.State == 0 ? 0 : 1)` —— Read 控制器：未领取=0（未读样式）、已领取=1（已读样式）。

**b__0（点列表项 → 详情）**：`if (!mailDic.TryGetValue(m_itemList.selectedIndex, out mail)) return;` 然后：
- `m_txtTitle.text = mail.Title; m_txtSenderName.text = mail.SenderName; m_txtContent.text = mail.Content;`
- 遍历 `mail.RewordArr`（附件），三个分支都调 `GetCoinFormat(item.Count)`（= `TabHelper.GetCoinFormat`，HotfixView rid 161：纯整数拆分 `Tuple<long,int,int>(arg/10000, (arg%10000)/100, arg%100)`，**无字符串格式化、无"亿"字面量**），分别取 `Item1/Item2/Item3.ToString()`：
  - `if (item.ItemId == 110203) m_txtGold = GetCoinFormat(item.Count).Item1.ToString()`（110203 数据表 `Name`="铜币"，UI 映射到 m_txtGold；示例 Count=150000000 → 显示 "15000"（万））；
  - `else if (item.ItemId == 110204) m_txtSliver = GetCoinFormat(item.Count).Item2.ToString()`（110204 数据表 `Name`="代金券"，UI 映射到 m_txtSliver）；
  - `else m_txtCoin = GetCoinFormat(item.Count).Item3.ToString()`（其他物品）；
  - 物品槽渲染：`m_btnRewordSlotLeft/Right.icon = UIPackage.GetItemURL("Bag", BagHelper.GetIconName(item.ItemId))`，`title = item.Count`。

**b__3 领取单封（TypeDef 1334，m_btnReceive）**：
```csharp
if (!mailDic.TryGetValue(ui.m_itemList.selectedIndex, out mail)) return;
if (mail.State == MailState.Received /* ==1 */) {
    TipHelper.OpenUI("此邮件的附件您已经领取过了!");   // toast，不发请求
    return;
}
var resp = await zoneScene.GetComponent<SessionComponent>().Session
    .Call<M2C_ReceiveMail>(new C2M_ReceiveMail { MailId = mail.Id, Page = currPage }); // 20283
if (!StringUtil.IsNullOrEmpty(resp.Message)) { TipHelper.OpenUI(resp.Message); return; }
ShowMailItem(resp.MailList, resp.MailCount);   // 20284 回整页列表
```

**b__4 删除单封（DisplayClass4_0.b__4）**：
```csharp
if (!mailDic.TryGetValue(ui.m_itemList.selectedIndex, out locals1.mail)) return;
locals1.currPage = this.currPage;
if (mail.State == MailState.UnReceive /* ==0 */) {
    TipHelper.OpenUI("此邮件含有【未领取的附件】，是否删除？");   // 有未领取附件的警告
    m_btnYes.onClick = BtnYesCallBack; TipHelper.AddEventCallBack(BtnYesCallBack);
}
// State==Received 时点删除无动作（客户端行为，注意勿在服务端据此设限）
```
**BtnYesCallBack（TypeDef 1338）**：`await Session.Call<M2C_DeleteMail>(new C2M_DeleteMail { MailId = locals1.mail.Id, Page = locals1.currPage })`（20285）→ Message 非空则 toast，否则 `ShowMailItem(resp.MailList, resp.MailCount)`。

**b__5 一键领取**：`TipHelper.OpenUI("保证您的背包空格数充足，否则物品消失，一概不负责！")` → `m_btnYes.onClick = RecieveAll`。
**RecieveAll（TypeDef 1335）**：`await Session.Call<M2C_ReceiveAllMail>(new C2M_ReceiveAllMail{})`（20287）→ 同上刷新（20288）。

**b__6 一键删除（TypeDef 1336）**：直接 `await Session.Call<M2C_DeleteAllMail>(new C2M_DeleteAllMail{})`（20289，**无确认框**）→ 同上刷新（20290）。

> 客户端分页约定：`currPage` 从 1 开始；上一页 `currPage>0` 才请求，下一页 `currPage<totalPage` 才请求；页大小由服务器决定（客户端不关心，只渲染返回的 MailList）。

### 3.2 聊天接收链路（Hotfix TypeDef 250/251 + HotfixView TypeDef 84）

**`M2C_SendNormalChatHandler.Run`（TypeDef 250，opcode 20300）**（async，`<Run>d__0`）：
```csharp
MessageInfo info;                                   // ChatMessageComponent.MessageInfo 结构体
info.name    = message.Name;
info.type    = message.Type;
info.content = message.Content;
info.time    = string.Format("{0:HH:mm:ss}", DateTime.Now);   // 字符串 0x70000BFC
ChatMessageComponent.Instance.Add(info);            // 按频道缓存（每频道上限 100 条，超了 RemoveAt(0)）
Game.EventSystem.PublishAsync(new EventType.AddChatUIText {
    zoneScene = session.ZoneScene, name = message.Name,
    chatType  = message.Type,     chatContent = message.Content,
    isSysBrocast = message.IsSystemBrocast,
});
```
`ChatMessageComponentSystem.Add`（TypeDef 353）：`messageDic[type].Add(info); if (messageDic[type].Count > 100) messageDic[type].RemoveAt(0);`。

**`M2C_SendSystemChatHandler.Run`（TypeDef 251，opcode 20301）**：
```csharp
foreach (string line in message.ContentList) {     // 逐行公告
    MessageInfo info = { name = message.Name, type = message.Type, content = line,
                         time = string.Format("{0:HH:mm:ss}", DateTime.Now) };
    ChatMessageComponent.Instance.Add(info);
    Game.EventSystem.PublishAsync(new EventType.AddChatUIText {
        zoneScene = ..., name = message.Name, chatType = message.Type,
        chatContent = line, isSysBrocast = message.IsSystemBrocast });
}
```

**`AddChatUITextEvent.Run`（HotfixView TypeDef 84，`<Run>d__0`）**：
```csharp
if (args.isSysBrocast) {                        // 同一正文进入界面中心全局播报队列
    MainUIGlobalText.Instance.Init(args.chatContent);   // 入队显示（m_txtGlobal）
}
MainUI.GetChatContiator().Refresh(args.chatType);       // 静态懒加载单例，重建聊天板
```
- `MainUIGlobalText`（TypeDef 23）：`Init(text)` 将文本 Enqueue 到队列，`Update` 用 `m_Effect` 过渡逐条播放。结合 `FUI_MainUI` 绑定可确认它是 MainUI 的**界面中心全局播报文本** `m_txtGlobal`，不是角色头顶聊天气泡。
- `ChatContiator`（MainUI 内嵌 TypeDef 1122）：
  - `InitChatContentList(GList)`：`gList.SetVirtual(); gList.itemRenderer = ListItemRender;`；
  - `Refresh(chatType)`：`contentList.Clear();` 若 `ChatMessageComponent.Instance.messageDic.TryGetValue(chatType, out list)`，将每条 `MessageInfo{time,name,content}` 连同 `chatType` 组入 **4 元组 `(chatType, time, name, content)`** 的 `List<Tuple<...>>` 并 `Add`；`ShowChatContentList()`（`gList.numItems = contentList.Count; RefreshVirtualList(); ForceShowChatBoard(); gList.ScrollToView(numItems-1)`）；
  - `ListItemRender`：把 4 元组 `(chatType, time, name, content)` 拼成完整聊天行：`m_txtType` 显示带频道色的 `[频道名 时间]`；`m_txtContent` 显示橙色、带下划线的发送者名称与冒号，随后原样拼接正文。等价格式为 `[color=<频道色>][<频道名> <时间>][/color][color=#FF9900][u]<发送者名称>[/u]：[/color]<正文>`。正文默认不是橙色；它使用控件默认白色，也可以由正文内的 UBB 标签分段改色；
  - `Add`：`contentList.Add(string.Format("{0:HH:mm:ss}", DateTime.Now) + ...)`，超 100 条 `RemoveAt(0)`。

### 3.2.1 公告文案、UBB 颜色与 Boss 播报边界

#### 客户端已确认的颜色能力

- 聊天行的世界频道标签由客户端固定为 `#00FFFF`，系统频道标签固定为 `#990000`；发送者名称固定为 `#FF9900` 并带下划线；聊天正文控件默认色为 `#FFFFFF`。
- 界面中心全局播报控件 `m_txtGlobal` 默认色为 `#FFFF00`，黑色描边，字号 30，单行显示。
- `FUI_LabelChatItem.m_txtContent` 与 `m_txtGlobal` 均开启 FairyGUI UBB 解析。服务端下发的 `Content` 可以使用 `[color=#RRGGBB]...[/color]` 对任意文案片段改色，**无需修改客户端**。
- `IsSystemBrocast` 只决定正文是否同时进入 `m_txtGlobal` 播报队列，不决定颜色。`Type` 决定聊天频道；正文颜色由控件默认色或正文中的 UBB 标签决定。
- 当 `IsSystemBrocast=true` 时，`M2C_SendNormalChat(20300)` 的同一个 `Content` 会同时用于聊天正文和中心播报。因此，显式写入 UBB 颜色的片段在两个位置颜色相同；未包颜色标签的片段在聊天行使用白色默认色，在中心播报使用黄色默认色。
- 已将 `client-test` 的 `Common_fui` 与用户提供的原版客户端资源进行 SHA-256 对比，两者一致；上述默认颜色和 UBB 能力是原版资源行为，不是旧客户端补丁造成的。

服务端可以自行定义公告文案及分段颜色，例如：

```text
[color=#FF8821]玩家名[/color] 击败了 [color=#FF4444]Boss名[/color]！
```

将这段内容放入 `M2C_SendSystemChat.ContentList`，并设置 `Type=System`、`Name="系统"`、`IsSystemBrocast=true`，即可让同一公告进入系统频道和界面中心播报。若产品明确要求进入世界频道，也可改用 `M2C_SendNormalChat.Content + Type=World`。玩家昵称等外部输入在拼入 UBB 前仍须经过名称规则校验或 UBB 转义，避免把用户输入解释成格式标签。

#### Boss 击杀与刷新协议的实际分工

当前 `server-mysql/boss.go` 的世界 Boss 击杀链路发送以下消息，显示作用不同：

| 消息 | 发送范围 | 客户端实际作用 |
|---|---|---|
| `M2C_BossDead(20065)` | 对应 Boss 层玩家 | 移除当前层 Boss 展示，不负责文字公告 |
| `M2C_BossBeDefeat(20066)` | 当前实现为全服 | 在现有客户端中未找到 Handler，仅作原生协议兼容，不能依赖它显示文字 |
| `M2C_SendSystemChat(20301)` | 全服 | `Type=System(7)` 写入系统频道；`IsSystemBrocast=true` 同时进入界面中心播报 |

Boss 定时复活时，`broadcastBossRefresh` 只向已经位于对应 Boss 层的玩家发送 `M2C_BossRefresh(20056)`。客户端收到后会在**当前场景**创建 Boss 模型，而且不会自行核对地图，所以 `20056` 不能全服发送，否则其他地图也会错误创建 Boss。文字公告另用 `M2C_SendSystemChat(20301)` 全服发送，模型刷新仍只向对应 Boss 层发送 `20056`。

公告范围应按玩法生命周期区分：

- `BossBase` 的 25 层地图 Boss 有死亡状态和定时复活，适合实现击杀、刷新世界公告。
- 每日活动世界 Boss 是一次性副本；当前没有定时复活公告链路。
- 家族 Boss 使用专用协议并持久化 HP；当前没有定时刷新协议，也没有证据表明原版会发家族或世界频道公告。
- 主线、试炼、死亡之塔等属于普通副本结算；当前没有全服击杀或刷新公告的原版证据。

现有抓包归档没有线上 `7756` 世界 Boss 击杀/刷新现场包，因此**原服的精确文案、是否每次刷新都公告，以及玩家名/Boss 名分别使用什么颜色，仍需线上抓包或原版截图确认**。当前实现依据客户端原生系统频道和用户截图，将刷新/击杀写入系统栏并保留中心播报；这是协议兼容实现，不能把当前自定义文案标记为“已还原原版文案”。

#### 战斗奖励实时系统消息

`M2C_SendReward(20084)` 的客户端 Handler 只播放经验、铜币和物品奖励弹字，不会写入聊天记录。当前服务端在每次发送非空 `20084` 后，紧接着发送一条 `M2C_SendSystemChat(20301)`：

- `Type=System(7)`、`Name="系统"`，确保进入客户端原生“系统”页；
- `ContentList(tag=1)` 按奖励拆成“获得经验：N”“获得铜币：N”“获得物品名 xN”；
- `IsSystemBrocast=false`，奖励只保留在系统栏，不让每场战斗的多行收益遮挡游戏中心；
- 所有 `20084` 出口统一走 `sendReward`，覆盖主线、普通/每日活动、单人和组队结算、试炼领奖及家族 Boss 奖励；空奖励不伪造系统消息。

`server-mysql/test/verify_maptest.py` 已通过真实 TCP 验证一场主线战斗同时收到 `20084` 与 `20301/System`，并实测正文包含经验和铜币。

```go
// C2M_GetMail(20281) → M2C_GetMail(20282)
func OnGetMail(p *Player, req *C2M_GetMail) (*M2C_GetMail, error) {
    page := max(req.Page, 1)
    list := p.db.MailsByPage(p.Id, page, PageSize)   // 含已过期但未删的
    return &M2C_GetMail{
        MailList:  toPbMails(list),                  // MailList tag=1
        MailCount: pages(p.db.MailCount(p.Id), PageSize), // MailCount tag=2 = 总页数
    }, nil
}

// C2M_ReceiveMail(20283) → M2C_ReceiveMail(20284)
func OnReceiveMail(p *Player, req *C2M_ReceiveMail) (*M2C_ReceiveMail, error) {
    m := p.db.GetMail(req.MailId)
    if m == nil || m.PlayerId != p.Id { return err("邮件不存在") }
    if m.State == MailState_Received { return err("此邮件的附件您已经领取过了!") }
    if len(m.Rewards) == 0 { m.State = Received; m.save(); return ok() }
    // 1) 入包（110203 铜币 / 110204 代金券走对应数值，普通物品走背包）
    if err := p.AddRewards(m.Rewards); err != nil { return err("背包已满") } // 附件消失提示见客户端文案
    // 2) 标记已领取 + 刷新本页
    m.State = Received; m.save()
    page := max(req.Page, 1)
    list := p.db.MailsByPage(p.Id, page, PageSize)
    // 3) 推 M2C_SendBag(20260) 更新背包（客户端唯一消费的背包推送）
    p.session.Send(&M2C_SendBag{ BagMapList: p.Bag.ToPb() })
    return &M2C_ReceiveMail{ MailList: toPbMails(list), MailCount: pages(...) }, nil
}
```

- `C2M_ReceiveAllMail`：遍历所有 `State==UnReceive` 邮件逐封入包（任意一封失败即中止并回 `Message`，客户端会 toast），全部成功后统一 `M2C_SendBag` + 回 `MailList/MailCount`。
- `C2M_DeleteMail` / `C2M_DeleteAllMail`：直接删除（**不要**因客户端"已领取才可删"的交互缺陷而限制服务端），回 `MailList/MailCount`。客户端删除单封只对 `State==UnReceive` 弹确认（有未领取附件的警告），`State==Received` 点删除无反应——属客户端行为，服务端按"允许删除任意状态"实现即可。
- 过期处理：`expire_ms < now` 的邮件可定时清理或在 `GetMail` 时过滤/置过期（`RemainTime` 是毫秒时间戳，客户端显示 `dd\天hh\时mm\分` 倒计时）。
- 邮件来源：CDK（`CdkConfig` 校验后发件）⚠ 推断/未证实、维护补偿（`MaintainRewardConfig` 按等级/战力发件）⚠ 推断/未证实、在线奖励（`OnlineRewardBase` 可直发或走邮件）、系统自定义。（数据表只提供配置，"按等级/战力发件"的筛选逻辑是推断。）

```go
// C2M_RequestChat(20298) → M2C_RequestChat(20299)
func OnRequestChat(p *Player, req *C2M_RequestChat) (*M2C_RequestChat, error) {
    if req.Type == ChatType_System { return err("不能发送系统频道") }          // 客户端已拦，服务端再拦
    if req.Type == ChatType_Private && req.Id == 0 { return err("私聊目标无效") }
    if p.isMuted() { return err("你已被禁言") }
    if len(req.Content) == 0 || len([]rune(req.Content)) > 200 { return err("消息过长") }
    content := IllegalWordFilter(req.Content)                                   // 敏感词过滤（服务端为准）
    msg := &M2C_SendNormalChat{ Content: content, Type: req.Type, Id: req.Id, Name: p.NickName } // 20300
    switch req.Type {
    case ChatType_Normal, ChatType_World:   // 世界/普通 → 全服或同场景在线玩家
        Broadcast(playersInSameScene(p), msg, exclude: p.Id)   // 不回发给本人（本地回显）
    case ChatType_Team:     Broadcast(teamMembers(p), msg, exclude: p.Id)
    case ChatType_Family:   Broadcast(familyMembers(p), msg, exclude: p.Id)
    case ChatType_Camp:     Broadcast(campPlayers(p), msg, exclude: p.Id)
    case ChatType_Private:  p.session.Send(msg); target := GetPlayer(req.Id); target.session.Send(msg) // 双方
    }
    return &M2C_RequestChat{}, nil          // Message 为空 = 成功（客户端本地回显）
}

// 系统公告（服务器主动）：M2C_SendSystemChat(20301)
func BroadcastSystem(lines []string) {

        online.session.Send(&M2C_SendSystemChat{

    }
```

- 客户端侧 `SendChat` 已拦截：`chatType == System` 与"私聊无目标"；服务端必须重复校验（防作弊）。
- 客户端有 GM 通道：`MyId==10001 && content.StartsWith("/cmd ctrl+o")` → `C2M_OpenGMUI`（服务端按需实现或直接拒绝）。

### 5.3 服务端自定义公告颜色

- 当前 Boss 刷新公告使用 `M2C_SendSystemChat(20301)` 并保留中心播报。击杀公告同样使用 `20301/System`，按实际参战队伍列出全部成员名称与角色 ID，并设置 `IsSystemBrocast=true`：客户端同时写入系统频道和界面中心全局播报，呈现原版的顶部击杀提示。
- 明确要求世界频道的其他公告可使用 `M2C_SendNormalChat(20300) + Type=World`；多条公告使用 `20301.ContentList`，客户端会逐条处理，频道仍由 `Type` 指定。
- 颜色直接写在 `Content` / `ContentList` 的 UBB 文本中，不需要客户端补丁。建议把具体公告模板和颜色作为服务端配置管理，但模板缺省值必须可用，并在热重载时校验 UBB 标签是否闭合。
- `20065`、`20056` 继续只承担 Boss 模型死亡/刷新；不要用场景实体协议代替文字公告，也不要为公告而扩大这两个协议的发送范围。

## 6. 验证要点（协议脚本可断言）

1. **邮件分页**：发 15 封邮件（10+5），`C2M_GetMail{Page=1}`（20281）→ `M2C_GetMail`（20282）断言 `MailCount==2`、`MailList` 长度 10；`Page=2` → 长度 5。翻页按钮 `currPage` 边界：Page=0/负数 → 服务端按 1 处理。
2. **邮件字段序列化**：`Mail{Title=2,Content=3,RemainTime=4,SenderName=5,State=7,Id=8}`、`MailItem{ItemId=1,Count=4,IsLock=5,IsHasItem=6}`、字段级 `Mail.RewordArr(tag6)` / `M2C_GetMail.MailList(tag1)` 必须按 tag 编码（用 `_check_pb.py` 类工具对抓包解码核对）；`RemainTime` 为毫秒时间戳，客户端 `FromUnixTimeMilliseconds` 解码。
3. **领取链路**：未领取（`State==0`）邮件 `C2M_ReceiveMail{MailId,Page}`（20283）→ `M2C_ReceiveMail`（20284）断言：`State` 变 1、`MailList` 是本页全量、**同时收到 `M2C_SendBag`（20260，BagMapList tag=1）**；重复领取同一封 → `Message` 非空（客户端 toast "此邮件的附件您已经领取过了!"）；背包满 → 返回错误且不消耗邮件。
4. **一键操作**：`C2M_ReceiveAllMail`（20287）/`C2M_DeleteAllMail`（20289）无业务字段（body 仅 RpcId/ActorId），响应 `MailList+MailCount` 全量刷新。
5. **聊天发送**：`C2M_RequestChat{Content(1),Type(2),Id(3)}`（20298）→ `M2C_RequestChat`（20299）成功时 `Message` 为空；Type=System 或 Private+Id=0 必须被拒；非法词被替换后广播。
6. **聊天广播**：玩家 A 在世界频道发言 → 同场景玩家 B 收到 `M2C_SendNormalChat`（20300，`Content(1)/Type(2)/Id(3)/Name(4)/IsSystemBrocast(5)`），**A 自己不收广播**；客户端本地回显，B 的聊天板 `ChatContiator.Refresh` 渲染，行格式 `[color=<频道色>][<频道名> <时间>][/color][color=#FF9900][u]<发送者名称>[/u]：[/color]<正文>`（见 §3.2）。
7. **系统公告**：`M2C_SendSystemChat`（20301）`ContentList(tag1)` 为字符串数组，逐条入缓存；`isSysBrocast=true` 时每条正文进入界面中心全局提示队列 `m_txtGlobal`，同时刷新 `Type` 指定的聊天频道。
8. **协议断言**（抓包/回放脚本）：opcode 20281/20283/20285/20287/20289 请求均带 `RpcId(90)`、`ActorId(93)`；响应带 `Error(91)/Message(92)`；`M2C_SendBag`(20260)、`M2C_SendNormalChat`(20300)、`M2C_SendSystemChat`(20301) 为单向推送（无响应配对）。
9. **UBB 与 Boss 公告**：下发 `ContentList=["[color=#FF8821]玩家A[/color] 击败了 [color=#FF4444]BossA[/color]！"]`、`Type=System`、`Name="系统"`、`IsSystemBrocast=true`，断言系统频道和 `m_txtGlobal` 均显示同一正文且两个显式着色片段正确；Boss 刷新时只向对应层发送 `20056`，文字公告另发全服 `20301`，并断言其他地图没有生成 Boss 模型。
10. **战斗奖励系统消息**：胜利结算断言先后收到 `M2C_SendReward(20084)` 与 `M2C_SendSystemChat(20301)`；后者必须为 `Type=System(7)`、`IsSystemBrocast=false`，并按非零奖励包含经验、铜币和物品正文。
