# 09 — 技能栏与主线战斗系统（自建服实现）

> 承接 07 文档。记录主城技能栏初始化/点击链路、主线战斗（MainStory）完整实现、
> datatable 配置表加载，以及「技能栏点不动」问题的修复过程。
> 代码实现位于 `server/battle.go` + `server/login.go`。

## 1. 技能栏初始化链路（客户端反汇编确认）

进入主城后，客户端 async `InitMainUISlotAndSetting` 流程：

```
InitMainUISlotAndSetting (TypeDef 1127 <...>d__4)
  ├─ 发 C2M_GetMainUISetting(20227) → await
  ├─ 收到 M2C_GetMainUISetting(20228)
  │    └─ publish UpdateMainUISlot 事件（携带 MainUISlotList）
  ├─ UpdateMainUISlotEvent.Run (TypeDef 144)
  │    遍历 MainUISlotList，按 Info.Index 取槽位 GComponent：
  │      MainUIType switch [258, 296, 348]  → 判定为【技能】槽
  │        （258/296/348 见 MainUIType 枚举：SkillSlot 等）
  │      非技能 → 按物品槽处理（Log.Error + GoodsBase.IconName）
  │      UIPackage.GetItemURL(info.Id.ToString()) 设置技能图标
  │      注册 onClick / onRightClick / onDrop
  └─ 循环每个子槽注册拖拽事件
```

**关键结论**：
- 技能槽 `Id` = 基础技能 ID（与 FGUI Skill 包图标名一致，如 `"100001"`）。
- SkillConfig 查表 key = **基础技能 ID × 100**（如 100001 → 10000100）。
- `MainUIType` 必须返回 `SkillSlot` 枚举值之一（258/296/348），否则被当物品槽处理。

## 2. 技能栏点击链路（客户端反汇编确认）

```
点技能槽 → onClick (TypeDef 1341)
  ├─ 读 MainUIType → switch 判定为技能
  ├─ 发 C2M_UseMainUISkill(20233) { SlotId = 槽序号 } → await
  └─ 检查 M2C_UseMainUISkill(20234)：
       Message 非空 → 误发 C2M_UseMainUIGoods(20235)
       Message 为空 → 技能生效
```

**关键结论**：20234 响应 **Message 必须留空**，否则客户端会误判为物品槽点击。

### 3.4 战斗流程

```
C2M_StartMainStoryFight(20048, Region)
  → 回 20049(空Message) + push 20047(InitMainStoryMap) + push 20050(怪物列表)
  → 服务器建 battleState（玩家 HP=500/MP=100/攻=25/防=5，怪物按 MonsterBase×HpTimes）

点击技能槽 C2M_UseMainUISkill(20233, SlotId)
  → 回 20234(空Message)
  → push 20075(PlaySkill) + 20077(Effect) + 20078(伤害，逐个目标)
  → 怪物死亡 push 20082
  → push 20237(StartCD)
  → 全灭 → emitVictory(20054 + 20084)
  → 否则 monstersAttack：存活怪物各打一次（20076 + 20078）
      玩家死亡 → 20083(UnitDead) + 20055(BattleDefeat)
```

- 伤害公式：`max(1, 玩家攻 - 目标防) × (1 + castValue×50)`；普攻 castValue=0。
- 技能类型：CastType 0=单体（打第一个存活）、1=群体（打全部存活）。
- 怪物攻击技能：取 MonsterBase.SkillGroupId → SkillGroupBase.SkillsArr[0].Skills_Id。

## 4. 「技能栏点不动」问题修复（重要）

### 4.1 现象

真实客户端登录进主城后，技能栏图标不显示、点击无效；客户端日志无报错，
服务器日志显示进主城后只剩 20333(ping)。

### 4.2 根因（服务器日志 + 反汇编定位）

客户端进入主城后固定发送 **20396 = `C2M_GetStarSoulBag`**，并 `await` 其响应
**20400 = `M2C_GetStarSoulBag`**。旧服务器 `handleOpcode` 无此分支（走 default 打
日志「未处理」）→ 客户端 await 永不返回 → 后续 `InitMainUISlotAndSetting` 流程阻塞
→ 技能栏点击事件未注册成功。

> 注意：20400 不是 20397！20397/20398/20399 分别是 `OpKVInt32Int64`/`OpKVInt32Int32`/
> `OpKVStringInt32`。星魂背包响应 opcode = **20400**（见 `protocol/opcodes.go:406`）。
> `M2C_GetStarSoulBag` 仅含 RpcId(tag90)/Error(tag91)/Message(tag92) —— 纯 ACK，无背包内容。

### 4.3 修复（server/login.go）

```go
case protocol.OpC2M_GetStarSoulBag:
    var req protocol.C2M_GetStarSoulBag
    if err = proto.Unmarshal(body, &req); err == nil {
        respOpcode, resp = protocol.OpM2C_GetStarSoulBag, s.onGetStarSoulBag(ch, &req)
    }

// 20396 → 20400：星魂背包查询。自建服暂无星魂系统，返回空 ACK（Message 空 = 成功）。
func (s *Server) onGetStarSoulBag(ch *channel, req *protocol.C2M_GetStarSoulBag) proto.Message {
    log.Printf("[S=%d] get star soul bag actorId=%d (no-op)", ch.id, req.ActorId)
    return &protocol.M2C_GetStarSoulBag{RpcId: req.RpcId}
}
```

### 4.4 通用教训

进主城后客户端会固定请求一系列「主 UI/背包」查询（20227、20396 等）并 await 响应。
**任何未处理的 opcode 都会让对应 await 卡住，进而阻塞整条 UI 初始化链。**
新增 UI 功能前先查 `protocol/opcodes.go` 中 `OpC2M_` 是否已被 `handleOpcode` 覆盖。

## 6. 怪物配置与点击判定（实机联调记录 2026-08-14）

### 6.1 点击判定链（OperaComponent.ClickTarget 反汇编，HotfixView.dll Rva=0x3830）

1. **只响应右键抬起**：`Input.GetMouseButtonUp(0)`（左键）成立时直接 `return 1`，什么都不做；
   只有 `GetMouseButtonUp(1)`（右键）才进入判定。→ 用左键点永远不会触发。
2. **前置阻挡**：玩家 `IsFight()`（战斗中）拦截；队伍任一单位 `MoveTimer != null`（移动/寻路中）拦截。
3. **距离限制**（CheckDis）：射线命中后 `(目标.position − MyUnit.position).sqrMagnitude > 6.25`
   （即超过 2.5 单位）→ 弹提示拒绝。→ 必须走到目标 2.5 单位以内。
4. **射线判定**：Physics2D.Raycast + layerMask，按 Monster→NPC→Player→SceneUnit 顺序命中，
   前提是目标 GameObject 有 Collider2D 且在对应 layer 上。

## 7. 点击进战斗 / 换层 / 数值属性（2026-08-14 实机修复）

### 7.1 血蓝显示 0

**根因**：客户端血蓝由 `NumericComponent` 管理，线上服务器进游戏时推
`M2C_SyncUnitAttribute(20169)` 初始化（NumericType：Hp=1001 / MaxHp=1002 / Mp=1003 / MaxMp=1004，
Str=1005 Quk=1006 Spi=1007 Wim=1008 PhyAtk=1009 SpiAtk=1010 PhyDef=1011 SpiDef=1012；
`ClientUnitCharacterComponent.Update` 只写 Id/名字/职业等，不写血蓝）。
**修复**：进游戏推 12 条 20169。⚠ 早期实现推的是固定值 `MaxHp=500/Hp=500/MaxMp=100/Mp=100/六维 10/攻 25/防 5`，
**该固定值早已移除**；现在推的是按线上模型算出的真实面板（1 级军训号 MaxHp=13000、MaxMp=702、
六维 1/1/13/1、PhyAtk=23、PhyDef=715、SpiDef=650，线值为显示单位的 100 倍），
见 11 文档 §2.3 与 `online_capture_panel_stats_test.go`。

### 7.2 点怪"战斗没了"（怪消失无战斗界面）

**根因**：`onClickMapUnit(20391)` 只回空 ACK → 客户端 `b__1` 回调 Message 空 → `Remove(unit)`
（怪消失）；而 `OnClickMonsterEvent` 按 `UnitSceneType` 分派，字段怪类型不匹配不发 20048 → 无战斗。
**修复**：`battle.go` 抽 `startMainStoryFightByRegion(region)`（建 battleState + 推 20047/20050），
`onClickMapUnit` 点击字段怪 → region=1001 主线战斗。验证：20391 → 20392 + 20047 + 20050 ✓。

### 7.3 战斗胜利不会自动传送到下一层

**根因**：客户端 `BattleEndEvent` 只 `BackPos()` 回战斗前位置，不请求下一层。
**当前正确行为**：`emitVictory` 只结算并记录本层完成状态，不自动换图。玩家回到战前位置后手动走入
本层末尾光圈，客户端再发送 `C2M_RequestEnterMap(20031)` 进入相邻下一层；服务端拒绝跨层和未完成本层时前进。
真实 TCP 验证：胜利收到 `20054+20084` 且不含 `20033`，随后手动请求 `1000602` 才收到 `ChangeMap` ✓。

### 7.4 换层（20031 传送点光圈）

`onRequestEnterMap(20031→20032)`：客户端点光圈带 `MapId` → `changeMap`（海滩 1000601~1000610
出生点 (-1.8,-0.84)，主城 10004）。`changeMap` 推 ChangeMap + StartupTransPoint 并更新 session.mapID。

## 8. 角色升级 / 属性成长 / 属性点

> ⚠ **本节 2026-09-14 复核更正。** 原「2026-08-14」版本记录的 `100·Lv³` 经验、500/100 血蓝基础、
> `Str = 10 + Str1·(Lv-1)`、每级 +1 属性点、等级上限 200 全部已作废，请勿再引用。
> 当前口径见 11 文档 §2.3 与 21 文档 §5。

- **升级经验**：`expNeed(Lv) = 100 * ⌊Lv³/100⌋`（100 倍定点存储，推 1027 时除以 100；
  **不设下限**，线上 1~4 级门槛就是 0）。战斗胜利 exp 累加（MonsterBase.Exp 之和），循环升级。
- **等级上限**：`maxPlayerLevel = 31500`（不再是 200）。
- **血蓝成长**：走 `CharacterGrowth`（按 `AttributeType*10+职业族` 查表，Σ 系数×六维）
  + 直接数值加成（装备/星魂/转生/宠物），**不再有 500/100 自建基础**；
  MaxHp/MaxMp 再乘星魂套装百分比。
- **六维**：基值 = `⌈阶段等级/10⌉`（不是 RoleGrowth 每级成长），再叠加手动加点与直接加成。
- **属性点**：**每 4 个阶段等级 +1**（不是每级 +1）；技能点每 200 级 +1。20253 AddPoint 分配
  （六行固定顺序 力量/智慧/体质/耐力/敏捷/精神），20255 ResetPoint 洗点。
- **同步推送**：升级/加点后 `pushPlayerAttrs`（12 条 SyncUnitAttribute，**推当前血蓝而非回满**）+
  `pushUnitCharacter`（SendUnitInfo 含 Level/CharacterPoint/Hp/Mp），角色面板/头像自动刷新。
- **持久化**：MySQL `players` 表保存 exp/char_point/skill_point/str_add/quk_add/spi_add/wim_add，
  以及当前 `current_hp`/`current_mp`（登录只钳上限、不补满）。
