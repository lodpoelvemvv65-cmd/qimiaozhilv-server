# 22-每日活动与五人战斗

> 当前实现日期：2026-08-18。本文记录 `C2M_StartActive(20409)` 的客户端事实、原版表映射、服务端行为和
> 真实 TCP 结果。与旧文档中“20409 空 ACK”或“只判活跃后直接发奖”的描述冲突时，以本文和当前代码为准。

## 1. 客户端入口与协议

`ActiveUI.<ShowDay>b__1` 点击活动项时只发送：

```text
C2M_StartActive { itemId = ActivePerDayConfig._id }  opcode 20409
M2C_StartActive { RpcId, Error, Message }             opcode 20410
```

客户端不在本地拼怪物或决定奖励。服务端必须按 `ActivePerDayConfig.BattleMethod/Params/Day` 分流；业务拒绝
使用 `Error=0 + Message`，避免该客户端把非零 RPC Error 当成会话异常。

服务端启动时加载四张原版表：

- `ActivePerDayConfig.json`：30 个入口、开放星期、方法和参数；
- `StarSoulCopyConfig.json`：5 类 × 4 难度 × 3 阶段，共 60 行；
- `WorldBossConfig.json`：活动世界 BOSS 的 3 个 `81001`；
- `JourneyOfDeathCopyConfig.json`：8 难度 × 2 阶段，共 16 行。

## 2. 四类活动

| 活动 | ItemId | CopyConfig / BattleType | 当前真实行为 |
|------|--------|-------------------------|--------------|
| 星魂副本 | 10001-10020 | 10014 / 23 | 按星期、Type、Difficulty 进入三阶段；第一阶段每名玩家扣 10 体力，后两阶段不重复扣 |
| 挂机战斗 | 10021 | 10010 / 4 | 按角色当前主线地图或不高于角色等级的最高线上 MainStory 区域建怪，扣 3 体力并立即启动自动战斗 |
| 活动世界 BOSS | 10022 | 10015 / 24 | 按 WorldBossConfig 创建 3 个 `81001`，无体力成本 |
| 死亡之路 | 10023-10030 | 10016 / 25 | 等级门槛依次为 6000/6500/7000/8000/9000/10000/11000/12000；每档两阶段，无体力成本 |

活动使用客户端已有的专用场景：星魂 A-E 为 `1004501..1004903`（每类三层），活动世界 BOSS 为
`1005001`，死亡之路为 `1005101/1005102`。开始时保存原地图坐标，阶段间切到下一专用层；完成、战败或
主动退出后回原地图坐标，不再把活动怪物叠到试炼层或留在活动场景。

战斗入口继承角色当前生命，不会暗中回满。当前生命为 0 时，单人或任一在线参战队员都会在切图、扣体力
和创建战斗前被拒绝并提示先恢复。这修复了上一活动战败后进入世界 BOSS 看似“被秒”的状态串场。

活动世界 BOSS 与 `BossBase` 的 25 层地图 BOSS 不是同一玩法。地图 BOSS 是单单位并使用 20061 专用展示、
死亡刷新倒计时；活动表明确配置三个单位，因此使用能够承载完整单位数组的 20050 战斗展示，并以
`BattleType=24` 结算，不写入地图 BOSS 的死亡/刷新状态。

## 3. 星魂奖励

每阶段读取该行 `StarSoulCountMin/StarSoulCountMax`，生成数量区间为：第一阶段 0-3、第二阶段 1-4、
第三阶段 5-8，完整一次活动合计 6-15 个。每个参战玩家独立生成并通过 `M2C_SyncStarSoulBag(20402)` 推送，
星魂背包和属性随玩家数据保存到 **MySQL**（⚠ 原文写“SQLite”是旧 `server/` 时代说法，已作废）；满 1000 容量后不越界。

`StarSoulTypeConfig.CopyType` 决定可掉落的套装类型，槽位来自 12 个装备位。客户端表给出四个副本难度和
六档星魂品质，但未发现“难度到品质的概率表”；当前只能用可证实的难度档作为品质档。此处是明确的
证据边界，不能声称已经还原不存在于当前包中的线上随机概率。

普通怪物经验及 `Dropasubset -> Parentset -> SonSet` 物品链仍按 `MonsterBase` 结算，背包满时沿用原子掉落
规则；每名玩家经验、物品、星魂和任务击杀独立结算。

## 4. 五人共享战斗

客户端只有五个玩家战斗阵位，怪物 HP 系数也是五档：`0/0.5/0.96/1.37/1.72`。因此服务器队伍上限为 5，
五人时怪物 HP 为单人的 `1 + 1.72 = 2.72` 倍。邀请、申请、接受均防止第六人进入。

每场多人战斗建立一个 `partyBattle`：

- 五端使用相同怪物 UnitId、MonsterId、HP 和 alive 状态；
- 玩家 UnitId、HP、MP、CD 和奖励各自独立；
- 任一队员施法，五端都收到 `20075 PlaySkill`、`20078 BattleSkillRet` 和 `20169` 绝对 HP；
- 全灭后每端只收到一次胜利和自己的奖励，所有 battleState 同时清理；
- 多阶段星魂活动由整队统一进入下一阶段，但体力只在第一阶段扣一次；
- 队员断线会从当前共享战斗/队伍摘除，并向剩余端推送新的全量 20162。

## 5. 回归结果

```text
go test ./...
go vet ./...
python server-mysql/test/verify_team.py
python server-mysql/test/verify_multiplayer.py
python verify_team5.py
python verify_active.py
```

2026-08-18 实测结果：

- `verify_team5.py`：玩家 3239-3243 组成五人队；五端收到相同的两个 `10001` 及 UnitId；第五人施法后
  五端技能、伤害、绝对 HP 均一致；五端各一次 `20054`；第五人断线后四端快照正确。
- `verify_active.py`：玩家 3244 依次进入星期二星魂 `10005`、3×`81001`、死亡之路 `90001` 和挂机；
  全部 20410 成功，战斗类型分别为 23/24/25/4，体力最终为 1987；6500 级入口对 6000 级角色正确拒绝。
- `active_test.go`：单人星魂三阶段、五人星魂三阶段、每人只扣一次 10 体力、每人 6-15 个星魂、
  世界 BOSS 和死亡之路线上阵容均通过。

这些测试不修改客户端补丁；全部通过正式 TCP `[u16 len][u16 opcode][protobuf]` 与当前服务进程交互。
