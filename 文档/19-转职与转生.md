## 1. 功能概述与入口

### 1.1 转职（TransferJob，20355/20356）

- **消息**：`C2M_TransferJob { jobType: int(1) } → M2C_TransferJob（空响应，仅 Error/Message）`
- **语义**：把角色职业切换到 `jobType` 指定的职业。`jobType` 取值是 `ET.JobType` 枚举（Hotfix.dll，TypeDef 410）：

  | 值 | 枚举 | 中文（ET.Profession） |
  |----|------|----------------------|
  | 0 | UnKnown | 全部 |
  | 1 | Officer | 军官 |
  | 2 | Sportsman | 运动员 |
  | 3 | Nurse | 护士 |
  | 4 | Superman | 超能力 |

- **客户端入口（重要发现）**：本客户端构建（2026.1.3.2）中**没有任何 UI 直接发送 C2M_TransferJob**——
  对 HotfixView.dll / Hotfix.dll 全部方法体扫描，`C2M_TransferJob` 只出现在消息类定义（Hotfix.dll rid 773）中。
  转职入口只有 GM 命令：`GMConfig.json`（共 27 条）中条目 `_id=1023` 的 `CMD="transJob"`（例 `transJob/1`，参数「职业 1/2/3/4」），
  经 `C2M_SendGMCMD`（20359）触发。新式角色界面 `FUI_CharacterUI`（HotfixView rid 205）的 `Awake`（实际位于 AwakeSystem，rid 204）
  只声明了 `m_btnPlusTransLevel`（child 26）/`m_btnMinusTransLevel`（child 27）/`m_txtTransLevel`（child 28）控件，
  **未挂任何点击回调**（字段仅被 Awake/Dispose 引用）——即转职 UI 未随包上线，转职逻辑完全由服务端承载，
  客户端通过 `M2C_SendCharacter`（20257）推送刷新角色数据即可。

### 1.2 转生（TransLevel，20342/20343）

- **消息**：`C2M_TransLevel { Level: int(1) } → M2C_TransLevel（空响应，仅 Error/Message）`
- **入口 1 — 任务/答题界面 Quest1UI**（HotfixView rid 597，旧式 UI）：
  `<AwakeAsync>d__5`（rid 1170）中 `m_btnTrans` 挂 `TransLevel` 回调；`TransLevel()` 是 async 状态机
  `<TransLevel>d__6`（rid 1171）：`new C2M_TransLevel { Level = 1 }` → Session.Call → await。
- **入口 2 — 管家/功能列表 ButlerUI**（HotfixView rid 522）：
  `AddTransLevel2()`（在 `m_taskList` GList 里 AddItemFromPool 一个按钮）→ `<AddTransLevel2>b__4_0` →
  `g__CallbackAsync|4_1`（rid 1052）：`new C2M_TransLevel { Level = 2 }` → Session.Call → await。
- **入口 3 — GM 命令**：`GMConfig.json` 另有条目 `_id=1019`：`CMD="TransLevel"`、`Example="TransLevel/昵称/0"`，
  经 `C2M_SendGMCMD`（20359）触发——第三条转生入口。
- ⚠ **含义（2026-09-14 更正，已由实现坐实）**：原文写「`Level` 是一次增加的转生等级数
  （1 = 加一转，2 = 加两转）⚠ 推断/未证实」——**推断是错的**。`Level` 是客户端选择的
  **目标转生阶数本身，不是增量**：`server-mysql/trans.go:120` 注释原文
  「req.Level ∈ {1,2} 是客户端选择的目标转生阶数，而不是增量；当前转生等级已达到目标时拒绝，
  避免一转点击二转后被错误写成三转」。实现为 `newTrans := req.Level`，
  若 `newTrans <= ss.trans` 则返回「已达转生等级」（`trans.go:136`）。所以**不是** `cur+Level`。
  转生等级即 `NumericType.Transmigration = 1029`
  （Unity.Model.dll 枚举确认），同时写回 `UnitCharacter.Trans`（tag 12）。
- 上述两个 UI 入口对响应的处理完全一致：`M2C_TransLevel.Message` 非空 → `OpenUI(Message)` 弹错误提示；为空 → 成功，UI 靠后续推送刷新。

## 3. 客户端处理链路（反汇编 IL 关键点）

### 3.1 转生请求 — Quest1UI.TransLevel（`<TransLevel>d__6`，HotfixView rid 1171）

```
ldarg.0; ldfld <>1__state; stloc.0; ldarg.0; ldfld <>4__this; stloc.1
ldloc.0; brfalse.s +…            ; 首次执行分支（state==0）
  ldarg.1; ldfld zoneScene
  (ZoneScene)                    ; zoneScene.CurrentScene()…

  dup; ldc.i4.1                  ; ← Level = 1（ldc.i4.1）
  callvirt C2M_TransLevel::set_Level
  … Session.Call(request, response)  ; await

  call StringUtil::IsNullOrEmpty
```

→ 客户端只发 `Level=1`，成功后无任何本地处理，全靠服务端推送刷新。

## 4. 相关数据表结构与字段语义

### 4.1 TransferJobConfig.json（职业技能索引表，22 条，全部 Type=1）

```
[key, {_id, Type:int, ids:int[4]}]
```

| 字段 | 语义 |
|------|------|
| _id | 技能槽/技能序号配置 id（1001-1022） |
| Type | 转职类型（当前全部为 1） |
| ids | 4 个技能 ID，索引 = 职业族：**[军官, 运动员, 护士, 超能力]** |

示例行：

| _id | Type | ids |
|-----|------|-----|
| 1001 | 1 | [100001, 200001, 300001, 400001]（四职业普通攻击） |
| 1002 | 1 | [110101, 210101, 310101, 410101] |
| 1003 | 1 | [110201, 210201, 310201, 410201] |
| 1021 | 1 | [120101, 220101, 320101, 420101] |
| 1022 | 1 | [120201, 220201, 320201, 420201] |

- 1001 是四职业普通攻击；1002-1022 是四职业对应的主动/被动技能。
- 转职时不能把 `ids[jobType-1]` 写进 `UnitCharacter.JobId`；那会把六位技能 ID 当职业编码，导致外观、性别、装备和属性全部错位。
- 当前服务端目标职业编码：`(JobType-1)*2 + sexOffset`，男性 `sexOffset=1`，女性为 2。
- 关联表：技能集合由 `TransferJobConfig/SkillConfig` 决定；装备职业限制仍使用 `EquipBase.JobId` 的职业族 1-4。

## 5. 服务器实现建议（Go；⚠ **实际实现在 `server-mysql/`**）

> ⚠ **本节伪代码勿照抄**，两处与实际实现不符：
> 1. `Level` 是**目标阶数**而非增量（`server-mysql/trans.go:120-138`，详见 §2）。
> 2. 门槛来自常量 `transLevelStart = {0, 6000, 13000, 21500, 31500}` / `transMaxLevel = 3`
>    （`trans.go:32,38`），**不是** `MainStoryExp` 或 `RoleGrowth` 曲线。
>    属性成长模型是 `CharacterGrowth`（键 = `AttributeType*10 + 职业族`），
>    `RoleGrowth` 仅用于离线反推经验公式。

### 5.1 转职 C2M_TransferJob（20355）

```go
type TransmigrationAddConfig struct {
    Id               int // 职业*10+转生等级 (11..43)
    AddAttributeArr []struct{ Key int; Value float64 } // Cal.AttributeType
}

// 20355 处理伪代码
func HandleTransferJob(s *Session, req *C2M_TransferJob) *M2C_TransferJob {
    if req.JobType < 1 || req.JobType > 4 {
        return message("无效职业") // 业务失败保持 Error=0
    }
    sexOffset := 1                            // 男；当前 JobId 偶数则为 2（女）
    if s.Char.JobId%2 == 0 { sexOffset = 2 }
    targetJobId := (req.JobType-1)*2 + sexOffset
    if jobTypeOf(s.Char.JobId) == req.JobType { return message("已经是该职业") }

    // 1) 更新职业
    s.Char.JobId = targetJobId                // 持久化并保持性别奇偶编码
    // 注：ET.NumericType（Unity.Model rid 282）全枚举无 JobId 成员（末位 PvpMoney=1047），
    // JobId 只经 UnitCharacter.JobId（tag 4）下发，不写数值组件。

    // 2) 删除旧职业技能；非基础技能按等级全额返还技能点（等级 L 返 L 点），免费基础攻击不返还技能点
    removeIncompatibleSkillsAndRefundPoints(s, req.JobType)
    // 补入目标职业 1 级基础攻击，并放到已学技能顺序首位
    ensureCurrentJobBaseSkill(s)

    // 3) 不符合 EquipBase.JobId 的装备原子卸下；背包空间不足则整个转职拒绝

    // 4) 推送刷新（客户端无本地处理，全依赖推送）
    Push(s, 20257, &M2C_SendCharacter{ UnitCharacter: buildUnitCharacter(s), Id: s.Char.Id })
    Push(s, 20170, &M2C_SyncUnitAttributeList{ UnitId: s.Unit.Id, NumericMap: s.Numeric.DirtyMap() })

    return ok() // 20356，Message 留空
}
```

### 5.2 转生 C2M_TransLevel（20342）

```go
// 20342 处理伪代码（⚠ 2026-09-14 更正：Level 是「目标阶数」而非增量，见本节顶部说明）
func HandleTransLevel(s *Session, req *C2M_TransLevel) *M2C_TransLevel {
    if req.Level != 1 && req.Level != 2 { return fail("转生参数错误") }

    newTrans := req.Level                                  // ✅ 目标阶数，不是增量
    cur := s.trans                                         // 当前转生阶
    if newTrans <= cur { return fail("已达转生等级") }      // 已到/超过目标即拒绝
    if s.level < transLevelStart[newTrans] { return fail("总等级不足") }
    // 注意：校验失败只填 Message，保持 Error=0（非零 Error 会被 Session.Call 当 RPC 失败断连）

    s.Numeric.Set(NumericType_Transmigration, float64(newTrans))
    s.Char.Trans = newTrans                                // UnitCharacter.Trans (tag 12)

    // 应用转生属性加成（按 职业*10+新转生等级 查 TransmigrationAddConfig）
    cfg := TransAddConfig[ s.Char.JobType()*10 + newTrans ]
    for _, a := range cfg.AddAttributeArr {
        s.Numeric.ApplyAttribute(a.Key, a.Value)           // 换算到 NumericType.Base/Add（如 力量1005→10051/10052 系）
    }

    // 推送刷新
    Push(s, 20169, &M2C_SyncUnitAttribute{ UnitId: s.Unit.Id, NumericType: NumericType_Transmigration, Value: float32(newTrans) })
    Push(s, 20257, &M2C_SendCharacter{ UnitCharacter: buildUnitCharacter(s), Id: s.Char.Id })

    return ok() // 20343，Message 留空（客户端只在 Message 非空时弹窗）
}
```

## 6. 验证要点（协议脚本可断言）

1. **请求-响应**（断言 Error=0 且 Message 为空字符串）：
   - `20342 C2M_TransLevel`：tag1 `Level=1`（或 2），含 RpcId(90)/ActorId(93)；
   - `20355 C2M_TransferJob`：tag1 `jobType=1..4`；
   - `20365 C2M_StartMainStoryAI`：tag1 `Index=0|1`；
   - `20367 C2M_EndMainStoryAI`：无业务字段。
2. **转生推送**：响应后应收到
   - `20169 M2C_SyncUnitAttribute{NumericType=1029, Value=旧值+Level}`（或 20170 批量），且 `Value` 单调递增、上限 3（⚠ 推断/未证实：上限由表反推）；
   - `20257 M2C_SendCharacter{UnitCharacter.Trans=新值}`，且 `UnitCharacter.Id == 请求方`。
3. **转职推送**：响应后收到 `20257 M2C_SendCharacter{UnitCharacter.JobId=目标 JobId}`；目标值为
   `(JobType-1)*2+sexOffset` 且保持原性别奇偶。旧职业技能和自动槽被清理，目标职业普通攻击以 1 级补入
   已学技能首位；职业编码、技能顺序和快捷栏一起持久化。旧存档缺少当前职业普通攻击时在登录时迁移补齐。
4. **数据表一致性**：
   - `TransmigrationAddConfig` 存在 `_id = 职业×10+新转生等级` 的条目（11/21/31/41、12/22/32/42、13/23/33/43）；
   - `TransferJobConfig` 各行 `ids` 长度 = 4，且每列技能 ID 属于对应职业族。
5. **异常分支**：转生已达 3 阶再请求或 `jobType=0/>4` → `Error=0 + Message` 业务拒绝，连接保持可用。
